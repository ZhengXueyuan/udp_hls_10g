## 1. 定稿修法

### 1.1 核心（`FIX-1`）：推进写的**域**搬一次，读保持原样

**一句**：**把 `snd_nxt` 的推进者从"发送引擎"改成"接收引擎"** —— 数据帧/重放帧的推进写发生在**帧接收收尾期**（`RX_FIN`，UDP 版 `udp_tx_frame.v:281-286` 那一族的拍上），写值取**该 bank 自己的不可变上下文**。⭐ **REV2 订正：具体落在 `RX_FIN` 的"首拍"（`fin_cnt==0`），不是"交棒拍/末拍"** —— 见下 §1.1-修订。

### 1.2 配套的统一门（`FIX-4`，也是 (i) 项的答案）

**RX 引擎的完整状态集（定稿，6 个语义相位 / 4 个状态）**：

```
RX_FLUSH  : 中止帧的 bank 冲洗 (FIX-3)
```

### 1.4 控制帧（`FIX-2'` 定稿：**帧首原子预留 + 槽跨拍独占 + 组合校验和**）

现役控制帧的 `+1` 写在 `S_DONE`（`:453-458` 的 `!is_data_r` 分支）。乒乓后它必须与 ① 的写分家，否则**撞写口**（§3-C1）。定稿三件：

**(1) 帧首原子预留**（原版保留）：

```verilog
// start_ack 拍 (RX 空拍), 与 :964 的 seq_r <= rb_snd_nxt 同拍同源:
//   seq_ctrl <= rb_snd_nxt;          ctrl_id <= start_id;  ctrl_syn/fin/rst <= aq_*;
//   upd_wr_ctrl = 1 (本拍组合), upd_id = start_id, upd_val = rb_snd_nxt + 32'd1;
//   条件: aq_syn | aq_fin | aq_rst     (纯 ACK 不占 seq, 与今天一致 ✓)
// 控制帧的 S_DONE 不再写 snd_nxt (upd_wr 只剩 ① 与 ③)
```

- 语义：FIN/RST/SYN 的 seq 一旦被分配，就在**同一拍**记进 TCB ⇒ **任何更晚启动的帧读到的基址都已含这次预留**。
- 与今天的关系：`fin_seq_r[cur_id] <= seq_r`（`:1134`）、`fin_sent_r`/`rst_sent_r`（`:1133/:1139`）、`fin_repush` 的两条守卫（`:675-677`）**全部不变**（它们不消费 `snd_nxt` 的写时点）。

**(2) ⭐ 槽的跨拍独占（REV2 新增；审查 F2 属实，缺它 = 丢帧/混帧）**

```verilog
reg ctrl_slot_busy;   // 槽**上下文占用**: 生命周期 = [start_ack, 该控制帧 T_DONE]  ← 挡 start_ack
reg ctrl_tx_pend;     // 槽里有**未发送**的帧: [start_ack, 该帧启动拍(进 T_HDR)]  ← 仲裁键 (REV3)
// start_ack 增: && !ctrl_slot_busy            (见 §1.2 表)
// 槽的装载拍 = start_ack; 上下文卸载拍 = 该帧 T_DONE (与 stat_ack/fin_sent_r 同拍)
//                      tx_pend 清位拍 = 该帧**启动拍** (TX 引擎离开 T_IDLE 进入 T_HDR 那一拍)
```

- **为什么必须有（上下文独占）**：拆引擎后 `state==S_IDLE` 这条隐含独占消失；`ackq` 深 32，`start_ack` 在 `rx_idle` 期间**每拍**都能再弹一个条目 ⇒ 第 2 个条目会在**前一帧还在被 TX 引擎逐拍读槽发头**（`T_HDR` 的 `hcnt 0..5`）时覆盖槽 ⇒ ① 前一帧被丢（且 `FIX-2'` 的预留已写进 TCB ⇒ **永久丢 FIN**，见 §3-C7）② 帧头字由**两个上下文拼出来**（w0 用旧、w3 用新 ⇒ 线上一个 seq/ack/端口混合的垃圾帧，见 §3-C8）。
- ⛔ **REV3 订正（审查二轮 R2 属实）**：原版把**仲裁键**也写成 `ctrl_slot_busy` —— **字面执行会重发同一控制帧**：控制帧**自己的 `T_DONE` 拍**也是一个"帧边界"，而该拍上 `ctrl_slot_busy` **仍为 1**（同拍卸载）⇒ 边界规则又选中控制帧，而槽里还是同一帧的上下文 ⇒ **同一 FIN/ACK 发两遍**（`stat_fin/stat_ack` 双计、对端收 spurious 重复 FIN）；更坏的复合：若此时 ackq 还有条目且 `rx_idle` 为真 ⇒ 下一拍 `start_ack` 重装槽，而重发帧正处 `T_HDR`（逐拍读槽）⇒ **C8 混拼帧从新路径复活**。
  ⇒ **修法 = 两个旗各管一件事**：**仲裁键 = `ctrl_tx_pend`**（"槽里有未发送的帧"）—— `start_ack` 置位、**该帧启动拍清位**；`ctrl_slot_busy` 只负责"挡 `start_ack`"（保护上下文），保持到 `T_DONE`。
- **TX 引擎的逐帧仲裁（槽 vs bank，REV3 修正后）**：每个帧边界（`T_IDLE` / `T_DONE`）判 `ctrl_tx_pend` ⇒ **先发控制帧**，否则发就绪的 bank ⇒ 保住"ACK 优先"的对端时延语义（`tcp_tx_frame.v:2-3` 的原设计意图）。控制帧**一旦启动** `ctrl_tx_pend` 即清 ⇒ 边界不会再重复选中它 ✓（它自己的 `T_DONE` 只做卸载与记账）。
- **代价与不变量**：两个旗都只挡 `start_ack` / 只影响 TX 引擎的逐帧选择（**不挡数据帧的采集** —— 数据帧走 bank）；**ACK 吞吐与今天同阶**（今天 `start_ack` 也 ≤1 次/控制帧）；条目**不会丢**（没弹走的条目留在 ackq 里）。
- ⭐ **REV3 订正（审查二轮 R3）**："无饿死"的**量**要写对：槽在**每次 `T_DONE` 后一拍**就可被重装（只需 `rx_idle && ack_pend_r && !ackq_empty`）⇒ 就绪的数据 bank 最坏被连续压后 **`ackq 深 × 控制帧时长 = 32 × 8 ≈ 256 拍`（≈1.3 个数据帧期）** ⇒ **有界、无死锁 ✓**。⛔ 原写的"必然在 **≤1 个数据帧期内**排空"**不对，已删**。
  - ⚠️ **TB 注意**：若相位扫描允许 `ack_req` 接近每拍脉冲（ackq 常满），可构造"数据帧被无限期推迟"的激励 ⇒ `cov_frames` 不达标 ⇒ **门自己作废（不是假绿）**；激励设计要么限制 ACK 洪泛，要么把这条写进已知陷阱。

**(3) ⭐ 控制帧的校验和 = 组合树（REV2 新增；审查 F3 后半问到了，原版没给）**

- 控制帧**无载荷但不是无校验和**（伪头 + 20 B TCP 头 + IP 头）。若沿用共享的 `checksum16`（单实例，`tcp_tx_frame.v:636-643`），要么与数据流的 `den` 撞（校验和错 ⇒ 对端静默丢弃），要么把 RX 引擎占住 5 拍（吞吐 −2.6%）。
- **定稿**：控制帧的 IP 校验和与 TCP 校验和**都在 `start_ack` 拍组合算出并锁进槽**（+32 FF）：
  - IP：现役已有纯组合函数 `ip_csum_calc`（`:593-606`），对控制帧取 `total_len=40`、`id_cap`、`dip` ✓；
  - TCP：**逐位等价于现役三次 `aen` 的结果** —— 已逐行核 `rtl/checksum16.v`：`acc` 只是**累加器**（`acc <= acc + add_val` / `+ wsum`），`fin` 出 `~fold16(acc)` ⇒ `~fold16(init_val + aen_v1 + aen_v2 + aen_v3)`（三项 = `:625-631` 逐字）**与三拍序列同值** ✓。
  - ⇒ **控制帧不再占 `checksum16`、不再占 RX 引擎、也不再需要 `S_WAIT` 的 5 拍**（其 TX 引擎占用 13 → **8 拍**）。
  - ⭐ **REV3 升格（二轮审查逐行核过）**：~~"仅纸面推导"~~ ⇒ **已坐实** —— `checksum16.v:47-49` 是**纯 32 位累加器**（`init→acc<=init_val(+den?wsum:0)` / `aen→acc<=acc+add_val` / `den→acc<=acc+wsum`），`:51` 只做**一次** `~fold16(acc)`；控制帧 `den≡0` ⇒ `acc = init_val+v1+v2+v3`（模 2³²）⇒ **32 位加法结合律** ⇒ 组合树逐位等价 ✓（`fold16` 对 32 位入参良定义、不会二次进位 ✓）；半字集合与字节序逐项对上（`sport/dport/seq_h/seq_l/ack_h/ack_l/doff_flags/wnd` = TCP 20 B 头的全部非零半字；`csum/urg` 计 0 ✓）。
  - ⚠️ **唯一实现约束**（照抄即得）：组合树必须用与帧头**同拍同源**的值（`start_ack` 拍的 `rb_snd_nxt/rb_rcv_nxt/doff_flags/条目 ack`），且**一次折叠、加完再折**（不许边加边折成 16 位）。
  - Gate A(ii) **仍保留**：它判的是**实现**（TB 侧从线上字节独立复算），不是这条定理。

**(4) 配套门（原版保留，语义收回）：**

```verilog
ctrl_adv_inflight_for(id) = ctrl_slot_busy && (ctrl_syn|ctrl_fin|ctrl_rst) && (ctrl_id == id);
upd_wr_rew = svc_rewind && !ctrl_adv_inflight_for(svc_id);
```

理由：预留后 `rb_snd_nxt` 在 FIN 在飞期间**领先 1**（`= fin_seq+1`）；若此时回卷，`retx_hi <= rb_snd_nxt` 就含这 1 字节 ⇒ `ring_delta = 1` ⇒ **在 FIN 的 seq 上重放 1 字节数据**（协议违规，G9 同族）。门后回卷推迟到该 FIN 落 `fin_sent_r` 之后（≤1 个帧期 ≈200 拍），G9 的 `retx_hi <= fin_seq_r[svc_id]` 规则随即生效 ⇒ 结构性排除。
- ⚠️ 门**只推迟**（`svc` 的其余动作一并推迟；`retx_gnt` 是电平握手 ⇒ tcp_rx 保持请求，最多晚 1.3 µs ≪ RTO 100 ms）。
- ⚠️ **门与槽独占的关系**：门的 `ctrl_slot_busy` 与 (2) 同源 —— 审查 F2 指出原版的门"救不了槽被覆盖的情形"；加了 (2) 之后槽不会再被覆盖 ⇒ 门的判据恢复有效 ✓。

**(5) ⛔ `FIX-2` 的定位订正（审查 F12 属实）**：原版写"`FIX-2` 与 `FIX-2'` 对 seq/ring/重放的**全部结论相同**，只差写在哪一拍"——**不成立**：

### 1.5 ⭐ `FIX-5`（**B4 定稿**）：重放引擎的落点 = **同一个 RX 引擎的第 4 个状态 `RX_RING`**

审查 F5 属实：原版把 §2.2 的互斥表建在"重放也有交接拍"上，却**没给重放的落点**。定稿 = **不另开引擎**（并进 `rx_state`）：

```verilog
// --- 启动 (Rx idle + bank 可用) ---  ring_eval && ring_start:
//   f_seq[rx_bank]  <= rb_snd_nxt;        // 重放基址 (REV2: 同上, 不加本地游标)
//   f_plen[rx_bank] <= plen_preset;       // = min(1460, ring_delta)      :576-578
//   f_conn[rx_bank] <= retx_id_r;  ...其余帧头字段同活帧 (TCB/CAM 读口)
//   beat_cnt <= 8'd1;  ring_seq <= rb_snd_nxt + 32'd8;  ring_rem/nbeats 同 :855-860
//   rx_state <= RX_RING;                  // ★ 第 4 个状态, rx_idle 期间进入
// --- 每拍 1 beat (写 bank FIFO + 过 checksum16), 末 beat = ring_fin ---
//   if (ring_fin) rx_state <= RX_FIN;     // ★ 与活帧**完全同一条收尾** (5 拍 aen/fin/latch + 交棒)
//   else begin beat_cnt <= beat_cnt + 1; ring_seq <= ring_seq + 8; end
// --- 推进写: 与活帧同点 (RX_FIN 首拍), 值 = f_seq[rx_bank] + f_plen[rx_bank] ---
```

- **为什么**：① 与活数据帧**共用 bank 资源**（`!bank_rdy[rx_bank]` 复用）；② 所有"帧首拍 / 收尾拍"事件落在**同一个串行器**里 ⇒ §2.2 的互斥表**由构造成立**（重放期 `rx_state == RX_RING ≠ RX_IDLE` ⇒ `rx_idle=0` ⇒ 活帧/控制帧/回卷都进不来 ✓）；③ `retx_ram` 的 2 级读流水（`:560-575` 的 `ring_d_r`）原样保留 ✓。
- **不写 ring**：`wr_tap`（`:549`）含 `accept`，重放的 beat 来自 `ring_wr`（内部）⇒ 结构性不重写 ring ✓（与今天一致）。
- ⭐ **REV3（审查 E①）写点二选一定稿**：重放的推进写**与活帧同点 = `RX_FIN && fin_cnt==0`**（不是 `ring_fin` 拍）—— `ring_fin` 只负责"末 beat 写完 + 转 `RX_FIN`"；`f_plen[rx_bank]`（= `ring_start` 锁存的 `plen_preset`）到那一拍仍是寄存器 ✓。⇒ 全文档**一个写点、一根 `upd_wr_data` 线**（§2.1）。
- **帧间零新增**：重放帧的下一块仍由 `ring_eval`（rx_idle 拍）启动 ⇒ `ring_delta` 单调减（§1.3-④）⇒ 会话终止 ✓。

### 1.6 `FIX-3`（审查 B3）：`len_bad`/`flush_pend` 与冲洗目标

- **可照抄**：`len_bad`/`flush_pend` 两个 flag 本身**照抄 UDP 版** —— 它们是 **RX 引擎的标量**（同一时刻只有一帧在被收），**不需要 per-bank 化**；
- **必须改（设计件 §3.4 归错的那一格）**：冲洗的**目标**必须是**当前接收 bank**（`rd_fl = (rx_state==RX_FLUSH) && !fifo_empty_rx`，`fifo_empty_rx` 按 `rx_bank` 选，UDP 版 `udp_tx_frame.v:205-207` 逐字如此）⇒ **结构性不可能抽掉另一 bank 在飞帧的载荷**；
- **判据**：`stat_drop_len` 与"被中止帧从不进 bank_rdy"两条（`BAD_LEN=1501/2000/4096` × 与在飞帧并发）。

### 2.1 写源表（定稿后 **3 个**；⭐ REV3 全域统一：活帧与重放合并、写点 = `RX_FIN` 首拍）

| 写源 | 触发条件（**逐字**） | 值 | 目标连接 |
|---|---|---|---|

> ① 该帧的 `f_seq`/`f_plen` 在那一拍**都已是寄存器**（活帧：帧首拍锁存 + TLAST 锁存；重放：`ring_start` 一次性锁存 `rb_snd_nxt` 与 `plen_preset`）✓

| 2 | W-数据 × W-回卷 | **否** | `svc` 要求 `rx_idle` ⇒ 同 1 |
| 3 | W-控制 × W-回卷 | **否** | W-控制含 `ack_pend_r`；W-回卷含 `!ack_pend_r`（`:297-298` vs `:334`，**今天的互斥关系逐字保留**）⇒ 恒不同拍 |
| 4 | ⭐ **"清 `ctrl_tx_pend`"（控制帧启动拍）× "下一条目 `start_ack` 置位"**（**旗 vs 旗**，REV3b-① 补） | **否** | **`pend ⊆ busy` 不变式**（`pend` 只在 `busy` 窗口内部清）+ `start_ack` 含 `!ctrl_slot_busy` ⇒ 重装不可能落在 `busy=1` 的任何拍上。**核过：与乒乓模板 `bank_rdy` 的"在飞/未发"角色分立同构**（`udp_tx_frame.v:201` vs `:396-401`） |

> ⛔ **REV3 删除**：原表的第 2/3 行用"`recv_first` **位互斥**"来推导 W-数据 × W-控制（因为旧写点与 `start_ack` 同处 `RX_IDLE`）—— 该推导随写点统一到 `RX_FIN` **失效并已删**；现在的依据是**状态互斥**（更强：`RX_FIN` ≠ `RX_IDLE`）。原第 1/4/5 行（W-数据 × W-重放、W-重放 × …）随两写源合并**一并消失**。

⇒ **`$onehot0({upd_wr_data, upd_wr_ctrl, upd_wr_rew})` 每拍成立 ⇒ TCB 单写口无争用**。**"两个 `S_DONE` 并发"这个问题在定稿里被消除，而不是被仲裁**。

### 2.2b ⛔ **同拍互斥 ≠ 无争用**（REV2 新增；审查 F2 的反证）

`$onehot0` 只覆盖**同一拍**；**跨拍独占**必须单独证。定稿给两条（原版**缺第二条** ⇒ 被审查 F2 用反例打穿）：

| 资源 | 独占窗口 | 谁保证 |
|---|---|---|
| **bank**（活帧 / 重放共用） | `[帧首拍, 该帧 T_DONE 归还]` | `!bank_rdy[rx_bank]` 接受门（UDP 模板 `:201` 逐字）+ 只在 `T_DONE` 归还（`:396`）—— 即**引理 L1** |
| **控制帧槽** | `[start_ack, 该帧 T_DONE]` | ⭐ **`!ctrl_slot_busy`**（`start_ack` 的新增项，§1.4(2)）—— 原版**没有这一项**，反例见 §3-C7/C8 |

⇒ **"单写口无争用"的完整证明 = 3 对同拍互斥 + 2 条跨拍独占**（原版只给了前一半；⭐ REV3：活帧/重放合并后同拍互斥从 6 对降到 3 对）。

### 2.3 若坚持保留 `S_DONE` 写（`FIX-2` 备选）

`FIX-2` = 控制帧的 `+1` 仍写在 `S_DONE`，但 **`S_DONE` 退出加门**：

```
ctrl_final_ok = !(is_syn_r|is_fin_r|is_rst_r) || (rx_idle && !svc);   // 纯 ACK 不门控
default: if ((!m_axis_tvalid || m_axis_tready) && ctrl_final_ok) begin … end
```

- 语义**与今天完全一致**（线序不变：末字早已发出，被推迟的只是"本地记账 + 下一帧启动"，≤ 一个帧期）；
- 代价：① `S_DONE` 完成路径新增一条 `rx_idle/svc → 末字消费` 的跨引擎路径（估 3–4 级 LUT，但**是新路径**，必须由构建裁决）；② 在极端构型下控制帧可能等到下一次 RX 空拍 ⇒ **窗口存在性 = 每帧至少 1 拍**（证明见 §2.4），必须进门的覆盖项。
- **选型裁定**：定稿用 `FIX-2'`（不动 TX 引擎完成路径、无窗口存在性问题、逻辑更小）；⛔ **REV2 订正（审查 F12 属实）**：原写"`FIX-2` = **等价替换**（两者对 seq/ring/重放的全部结论相同）"—— **不成立**：至少"**控制帧条目丢失**"这一支**行为相反**（`FIX-2` 下 `fin_push` 的 `snd_nxt==snd_una` 仍真 ⇒ 下一轮扫描自愈；`FIX-2'` 的预留把它**永久**打掉），且 `FIX-2` 会让"`+1` 在 TX 完成后才改 `snd_nxt`"成为**第二套语义**。⇒ `FIX-2` 降级为**备用方案**，启用前必须**重证三项**：`fin_push` 的重挂路径 / `ring_delta` 的拍账 / 那条跨引擎新锥（§1.4(5) 表）。

### 2.4 （`FIX-2` 专用）窗口存在性证明 —— 也给 `FIX-2'` 当参考

稳态（两引擎都饱和）：`RX 完帧(R)` ⇒ `rx_bank ← T`（`T` = TX 正在发的 bank）⇒ 接受门因 `bank_rdy[rx_bank]=1` 关；`TX 完帧(T)` 的下一拍 ⇒ `bank_rdy[T]=0` 可见 ⇒ **该拍就是 RX 空拍**（`rx_state==RX_IDLE && recv_first`）⇒ 每帧至少 1 个空拍 ⇒ 无死锁、无饿死。**这条要进门**（统计"RX 空拍次数/帧" ≥ 1）。

## 3. 反例驱动：9 个具体损坏/死锁场景 + 逐条排除

> 每个都给：**触发条件（可写成激励）/ 后果（可观测）/ 修法怎么排除 / 哪个门必然抓**。
> ⭐ **REV2 订正**：原版 C5 经审查 F6 判定为**幻影**（结构性不可达 ⇒ "门必然抓"做不到）⇒ 降级并保留证明；**新增 C7/C8**（控制帧槽覆盖 / 帧头混拼）= 一轮审查抓到的最重一条，它同时是"同拍互斥不充分"的**反证**。
> ⭐ **REV3 新增 C9**（仲裁键用"槽忙" ⇒ 控制帧 `T_DONE` 拍自重发；二轮审查 R2）。

### C1 —— **同拍撞写口**（若 W-控制 留在 `S_DONE` 且不加门）

- 触发：一个 FIN 的 `S_DONE` 恰好与一个数据帧的交接拍同拍（相位由 app 的到达时刻决定，**随构型变**）。
- 后果：TCB 单写口只能落一个（组合优先级决定）；丢 `+1` ⇒ `snd_nxt` 永久少 1 ⇒ 下一个数据帧**复用 FIN 的 seq**（对端判 spurious）；丢推进 ⇒ `snd_nxt` 少一整帧 ⇒ 该帧数据被下一次发送覆盖（**静默损坏**）。
- 排除：§2.2 的状态互斥（`FIX-2'`）。
- 门：**Gate B**（`$onehot0` 每拍断言）+ **相位扫描覆盖**（否则这个门会空转）。

### C2 —— **反向写（`snd_nxt` 回退）**

- 触发：某连接的 FIN/RST 已启动（预留/在飞），而一个**更早启动**的数据帧的推进**落地更晚**（乒乓下完全可能：data 在 bank 里被 MAC 拖慢，ctrl 走了控制槽）。
- 后果：`snd_nxt` 从 `base+plen` 回退到 `base+1` ⇒ `(snd_nxt − snd_una)` 缩水 ⇒ 窗口门**多放帧**（ring 压力）；且下一帧基址回退 ⇒ **重发已确认数据 + 对端 dup-ACK 风暴**；极端下 `snd_nxt < snd_una` ⇒ 32 位下溢 ⇒ `win_open ≡ 0` ⇒ **数据面冻结**（靠 RTO/回卷自愈，代价一个 RTO ≈ 100 ms）。
- 排除：`FIX-2'` 让控制帧的写在**帧首拍**落地（早于任何更晚启动的帧）⇒ 恒为前向。⛔ **REV2 订正**：原写"**并且**给数据帧的推进加 `f_plen != 0` 门"—— 该门**已删**（§3-C5 判为幻影的配套），本卡的排除**只靠"写在帧首"这一条**；变异 `M-C2`（形态见 §4.5）**就是本卡的判据**。
- 门：Gate A 的 `J_seq_mono`（每连接 `snd_nxt` 只准在 `svc`/`cfg` 边沿后退，其余拍必须单调不减 → 用层次引用采 `upd_wr/upd_val` 重建）。

### C3 —— **回卷与在飞帧乱序 ⇒ `retx_hi` 少一段（数据永久丢失）**

- 触发：**若**推进留在 `S_DONE`（即"乒乓骨架 + 只本地化 ring 游标"的半修法）：`svc` 拍 `retx_hi <= rb_snd_nxt` 时，bank 里已收完但未发完的那一帧的推进**还没落地** ⇒ `retx_hi` 少一帧 ⇒ 重放区间 `[snd_una, retx_hi)` **不含那一帧的字节**；而重放结束后 `snd_nxt` 会走到 `retx_hi`（甚至被那一帧的 `S_DONE` 写推过它）⇒ 对端永久缺这一段 ⇒ **停流**（且板侧计数"干净"）。
- 后果等级：**静默 + 停流**（本工程最贵的一类）。
- 排除：**`FIX-1` 的直接理由** —— 推进在 `RX_FIN` 落地 ⇒ `svc` 拍读到的 `rb_snd_nxt` 已是"全部收完帧都算上"的**承诺前沿** ⇒ `retx_hi` 精确（重放把它们一并重发，幂等）。
- 门：Gate A 的 `J_replay_cover`（重放必须**逐段覆盖** `[snd_una, retx_hi]` 且不留空洞）+ **变异 `M-C3`**（把推进搬回 `S_DONE`）**必然红**。

### C4 —— **重放自锁（无限重放同一块）**

- 触发：重放基址/游标与推进不同域：`ring_start` 读 `rb_snd_nxt`，而 `rb_snd_nxt` 只在重放帧**发完**才推进 ⇒ 第二个重放块的基址仍是上一块的基址 ⇒ `ring_delta` 不缩。
- 后果：同一 1460 B 无限重放（`stat_retx` 不涨、`ring_eval` 永久占住 RX 引擎 ⇒ **活数据永不启动 = 停流**），且线上同 seq 无限重复。
- 排除：`FIX-1` ⇒ 重放帧的推进落在**它自己的交接拍** ⇒ 下一个 `ring_eval`（RX 空拍，晚 ≥2 拍）读到 `base+plen` ⇒ `ring_delta` 单调减 ⇒ 归零收尾（`:889-901` 的排空拍逻辑**逐字不变**）。
- 门：Gate C 的 **会话终止判据**（`retx_req` → `o_retx_active` 落 = 有界）+ **变异 `M-C4`**（重放基址本地化但推进滞后）必红。

### C5 —— ⛔ **幻影（降级；审查 F6 属实）**：0 长帧的"写同值"回退

- 原主张：`plen = 0` 的数据帧推进写 = `base + 0 = base`，若落在同连接 FIN 预留的 `+1` **之后** ⇒ `snd_nxt` 从 `F+1` 退回 `F` ⇒ 窗口下溢/冻结（同 C2）。
- ⛔ **为什么它打不出来（两条，逐条给依据）**：
  1. **顺序被结构钉死**：`start_ack` 要求 `rx_idle`（§1.2）；0 长帧的接收期 `recv_first=0` ⇒ `rx_idle=0` ⇒ **FIN 的预留必然晚于该帧的 `RX_FIN` 推进写**；其后 `tx_blk`（`fin_req` 电平在 ESTAB 期间恒高，`rtl/app_ctrl.v:1097-1100`）挡住该连接的新数据帧 ⇒ 反向顺序**不可达**。
  2. **"写同值"本身不可观测**：在该帧的接收期内，`svc`/`start_ack` 都要求 `rx_idle` ⇒ 没有任何写能改变 `rb_snd_nxt` ⇒ `base+0 == base` = **幂等写**（不产生"回退"，也因此 `J_seq_mono` 单调不减恒成立 ⇒ 判据看不见）。
- ⇒ **处置**：① **删掉原版的 `f_plen != 0` 门**（一个永远为真/永远打不出红的守卫 = 自造真空门）；② **删掉原 M6 变异**；③ 本卡保留为"**结构性不可达（附证明）**"，不再声称"门必然抓"；④ 若日后有人拆掉这条结构（例如再加一个采集引擎），本卡**复活**。

### C6 —— **回卷与在飞 FIN 的 1 字节重放**（`FIX-2'` 自身的配套风险，已用 §1.4(4) 的门排除）

触发：FIN 预留后（`snd_nxt = F+1`）在 FIN 落地前发生回卷 ⇒ `retx_hi = F+1`、`ring_delta = 1` ⇒ 在 `F` 上重放 1 字节数据。排除 = §1.4(4) 的 `!ctrl_adv_inflight_for(svc_id)` 门。门 = Gate A 的 `J_fin_resv` + 变异 `M-C6`。
⚠️ **REV3 补充（与 §7.2-退路1 联动）**：若采用 ENQUEUE 预留，该门的判据必须**改键**到"**预留未发**"窗口（新增 `fin_resv[15:0]`：enqueue 置、T_DONE 清）—— 否则窗口从 `[start_ack, T_DONE]` 拉长到 `[enqueue, T_DONE]` 而门没跟着扩 ⇒ **本卡在更长窗口里复活**。

### C9 ⭐（REV3 新增；二轮审查 R2）—— **仲裁键用"槽忙" ⇒ 控制帧自己 `T_DONE` 拍被重发**

- **触发（纸面规则的字面执行）**：`start_ack(T)` 装载槽（`busy=1`）→ TX 空闲 → `T+1` 起发控制帧（8 拍）→ `T+9` = 该帧 `T_DONE`（**`busy` 在该沿才清**）→ 帧边界判定读到 `busy=1` ⇒ **又选控制帧**，而槽里还是同一份上下文 ⇒ **同一 FIN/ACK 发两遍**。
- **后果**：`stat_fin/stat_ack` 双计；对端收 **spurious 重复 FIN**；若此时 `ackq` 还有条目且 `rx_idle` 为真 ⇒ 下一拍 `start_ack` 重装槽，而"重发帧"正处 `T_HDR`（逐拍读槽）⇒ **帧头两代上下文拼出 = C8 复活**。
- **排除**：§1.4(2) 的**仲裁键 = `ctrl_tx_pend`**（`start_ack` 置位、**该帧启动拍**清位）⇒ 控制帧一旦启动就不再被边界选中 ✓；`ctrl_slot_busy` 仍在 ⇒ 槽不可能在其 `T_HDR` 期间被重装 ✓。
- **门**：Gate A(i) **控制帧守恒**（`issued_FIN == transmitted_FIN`，重复发 ⇒ `transmitted > issued` 必红）+ 变异 `M-C7` 的姊妹变体（把仲裁键改回 `ctrl_slot_busy` ⇒ 守恒必红）。

### C7 ⭐（REV2 新增；审查 F2）—— **控制帧槽被覆盖 ⇒ 永久丢 FIN + 后续 1 字节静默重放**

- **触发**（可写成激励）：① 连接 3 app close ⇒ `fin_req[3]=1`；② 扫描 `fin_push`（`:659-661`）把 FIN 条目压进 `ackq`（深 32）；③ TX 引擎此刻正在发**另一连接**的 1514 B 数据帧（占 ~191 拍，槽空不出来）；④ **同一批到达的第 2 个控制帧**（例：连接 5 的 RST，或任何 ACK 条目）在 `start_ack` 拍被弹出。
- **后果链（逐条有行号）**：后一个覆盖前一个 ⇒ FIN 从未上线，但 `FIX-2'` 的 `+1` **已写进 TCB**：
  1. `snd_nxt[3]=F+1`、`snd_una[3]=F` ⇒ `fin_push` 的 `rb_snd_nxt == rb_snd_una`（`:661`）**永久为假** ⇒ **FIN 再无首发路径**；2. `fin_sent_r[3]` 恒 0 ⇒ `fin_retx_pend` 不置位（`:822`）⇒ **RTO 重推也无入口**；3. 但扫描仍给它装 RTO（`:942-943`）⇒ RTO 到期 ⇒ `svc` 回卷 ⇒ `retx_hi = F+1`、`snd_nxt := F` ⇒ **`ring_delta = 1`** ⇒ `ring_start`、`plen_preset = 1` ⇒ **把 ring 里 `[F,F+1)` 那 1 个字节（上一圈残留）当数据发上线**（seq=F 正是对端 `rcv_nxt` ⇒ 窗口内合法）⇒ **静默数据损坏**，且 FIN 仍未上线；4. 原版 §1.4 的门**救不了**（槽已被覆盖 ⇒ `ctrl_*` 指向第 2 帧）。
- **排除**：§1.4(2) 的 `!ctrl_slot_busy`（条目不再被覆盖 ⇒ 该链的**第一步**就不成立）+ §1.4(4) 的门（兜第二层）。
- **门**：⭐ **Gate A(i) 控制帧守恒**（`issued_FIN == transmitted_FIN`，且每个条目在 N 拍内上线）+ `J_fin_resv`；变异 `M-C7`（撤 `!ctrl_slot_busy`）**必红**。

### C8 ⭐（REV2 新增；审查 F2 的第二形态）—— **槽被覆盖落在 `T_HDR` 期间 ⇒ 线上"混拼帧"**

- **触发**：同上，但覆盖拍落在 TX 引擎的 `T_HDR`（`thcnt 0..5` **逐拍读槽**）中间。
- **后果**：帧头字由**两个上下文**拼出（w0 用旧、w3 用新……）⇒ 线上一个 **seq / ack / 源端口 / MAC 混合**的垃圾帧（对端可回 RST）；且 `+1` 记给了错的那一个连接 ⇒ `snd_nxt` 归属错误（静默）。
- **排除**：同 C7（槽独占 ⇒ 混拼不可能）；另加 `start_ack` 的 `rx_idle` 项（原版**漏写**，见 §1.2 表）⇒ 控制帧的 seq 锁存与预留**只在 RX 空拍**发生 ⇒ 同连接的数据帧采集期不可能插入控制帧。
- **门**：`J_payload`（逐帧内容 oracle，含头部字段）+ Gate A(ii) 校验和 oracle（混拼帧的校验和必错）+ 变异 `M-C8`（把 `start_ack` 的 `rx_idle` 项删掉 + 相位扫描）**必红**。

## 4. 判据：能写出来的门（回答"门写不出来"）

> 结构性思路：**判据不读 DUT 自己的寄存器来判 DUT 的账**（全局 #32 同源 oracle 的教训）。内容用**TB 侧独立影子账本**，速率用**拍/帧**，写口用**每拍 $onehot0 + 覆盖见证**。

### Gate A —— **seq/内容 oracle**（`_proj_10g/tcp_ovl/sim/run_tb_tx_ovl_seq.bat` + `tb_tcp_tx_ovl.v`）

- **激励**：合成 app 源（长度扫 `0/1/7/8/63/1460/1500/1501(中止)/4096(中止)`；帧间气泡扫 `0..255` 拍 ⇒ **相位扫描**）× 多连接（3 条交织）× 独立时钟化的 `ack_req`/`fin_req`/`rst_req`/`retx_req`（dup-ACK 注入点也做相位扫描）× 程序化 ACK（TB 当对端，自己决定 ACK 到哪）。
- **判据（每条都必须是计数器 = 0，末尾打印）**：
  1. `J_seq_cont`：活数据帧按传输顺序的 `[seq, seq+plen)` **连续不交**；
  2. `J_seq_mono`：每连接 `snd_nxt` 单调不减（除 `svc`/`cfg` 边沿），且**永不 < snd_una**。<br>　**观察法（必须写进 TB；⭐ REV3 按二轮审查 R5 补全前提）**：层次引用 DUT 的 `upd_wr/upd_val/upd_id` **逐拍重建影子 TCB**（与 Gate B 同一套探针），把每次写按 id 记账；**不读 DUT 的 TCB 阵列**（同源 oracle 禁令，全局 #32）。**两个成立前提**：(a) 影子账本要能区分 **`svc`/`cfg` 边沿**（`svc` 由同一套探针识别；`cfg` 侧写口 = wrapper `:1958-1961` 的 `scfg_upd_*` 级）；(b) "**永不 < `snd_una`**"这一条要求影子账本**同时记非 tx 写口** —— **`cfg` 的建连初始化** + **`tcp_rx` 的 `snd_una`**（wrapper `:1968-1970` 的 rx 级）—— 否则这条判据**没有比较基**。这条是 `M-C2` 的判据；
  3. `J_payload`：每帧载荷**逐字节** = TB 源流对应区段（这条抓 C1 的 ring 覆盖）；
  4. `J_replay_cover`：回卷后重放**逐段覆盖** `[snd_una, retx_hi]`、无空洞、不越界；
  5. `J_fin_resv`：FIN/RST 的线上 seq = TB 影子账本算出的 `snd_nxt@启动`；且 `svc_rewind` 与"在飞 FIN/RST"不重叠；
  6. `J_ringwin`：`wr_tap && w_tap_seq` 观察到的 ring 写区间 == 该帧的 seq 区间（层次引用，不新增端口）。
  7. ⭐ **REV2 新增 (ii)：逐帧 TCP/IP 校验和 oracle** —— TB 侧从**捕获到的线上帧字节**独立复算以太/IP/TCP 三个校验和（含伪头、`total_len`、`seq/ack/wnd`），**逐帧断言相等**。它抓的是"共享 `checksum16` + 三个帧源"这一新失败类（F3 后半）：控制帧的校验和窗口被数据流的 `den` 污染 ⇒ **ACK/FIN 的 TCP 校验和错 ⇒ 对端静默丢弃**。也顺带判 §1.4(3) 的组合树是否与三拍 `aen` 逐位等价。
  8. ⭐ **REV2 新增 (i)：控制帧守恒** —— `issued_X == transmitted_X`（X ∈ {SYN, FIN, RST}，条目不丢）且 `issued_ACK == transmitted_ACK + stat_ack_drop`（纯 ACK 允许丢、但必须记账）；附"**每个 `start_ack` 条目必须在 N 拍内上线**"（N = 32×帧周期）的延迟上界。
- **覆盖见证（缺一条则整门作废 = 门是空的）**：`cov_frames ≥ 2000` · `cov_replay_sessions ≥ 5` · `cov_conns ≥ 3` · `cov_plen0_frames ≥ 1` · `cov_aborts ≥ 2` · `cov_ctrl_data_write_adjacent(cycle_gap ≤ 1) ≥ 20` · ⭐ **REV2 新增 (iii)**：`cov_data_fin_to_next_start(min_gap == 1) ≥ 20`（**"上一帧 `RX_FIN` → 下一帧首拍"撞到最小间隔的命中数** —— 这一格是 F1 的零余量/最小余量格，没有它，"间距足够"就只是没测到）+ `cov_ctrl_slot_overwrite_blocked ≥ 20`（**槽忙时 `start_ack` 被挡住的实际命中数** —— C7/C8 的判据只有在"本来会被覆盖"的时刻才有效）。

## 6. 与 R2（app TX 8 路 / 1 拍一字）的接口

### 6.1 联合拍/帧与 Gbps（**订正后的口径**）

```

帧周期 = max(190, 189, 191, 193) = 193
载荷   = 1460/193 × 156.25 MHz = 7.5648 B/拍 = 1.1820 GB/s = 9.456 Gbps
       = 理论线位上限 9.4928 (1460/1538×10) 的 99.61%
```

### 6.3 ⭐ **双向预算（REV2 新增；审查 F7 末段列为待办，本版并入）**

- **事实**：`APP_MODE` 下快路径**每收一个数据帧就发一个纯 ACK**（`board/wrapper_p4.v:1767` 的 `cfg_suppress_data_ack(!APP_EN)`）⇒ "单路双向"构型里，TX 线上每 193 拍还要插一个控制帧。

#### ⭐ §6.3-**核**（REV3b 事实核对：MAC 侧开销，**只读** `_proj_10g/p7b_mac/rtl/mac_tx_10g.v`）

> **先说这段的边界**：我核的是**该 MAC 自身的逐帧结构**（状态机 + 常量 + 注释里的算数），**不是**板级读数；两处数字（193 / 11）里 193 有板级锚（`ΔW43/ΔW20 = 192.999989`），11 是**结构值**。

**A. 该 MAC 的每帧公式**（`mac_tx_10g.v:14-20` 头注 + `:274-286` CRC/合并字 + `:333-430` FSM 逐行）：

```
每帧 XGMII 拍数 = 1(S_PRE, 前导只占帧首那 1 拍的 lane) + ceil(L/8)(S_DATA, 末字与 FCS 合并, 不额外占拍)
                + [需要 S_TAIL0 ? 1 : 0](纯 pad 续字) + [需要 S_TAIL1 ? 1 : 0](FCS 尾 + /T/ + /I/)
                + IFG(1~2)(S_IFG 每拍发一个满 /I/ 字, 凑够 >= 12 个 /I/ 才结帧)
   L = 内容长度 (含 pad 到 ETH_MIN_CLEN = 60, 不含 FCS 4 B —— FCS 由 MAC 加)
```

**B. 用这个公式复现两个锚**（这是"核过"的证据）：

| 帧 | 逐拍分解（RTL 状态序） | 合计 | 对锚 |
|---|---|---|---|
| **数据帧** 内容 1514 B | `S_PRE 1` + `S_DATA 190`（1514/8 向上取整；末字 2 B + FCS(4) + /T/ + 1 个 /I/，`lw_ts = 2 ≤ 3` ⇒ **不需要 S_TAIL1**） + `S_IFG 2`（尾字已带 1 个 /I/ ⇒ `1+8 = 9 < 12` ⇒ 再一发 ⇒ 2 拍） | **193** | ✅ **与板级 `ΔW43/ΔW20 = 192.999989` 逐数吻合** |
| **ACK 帧** 内容 54 B（TCP 20 + IP 20 + Eth 14，无选项） | `S_PRE 1` + `S_DATA 7`（54 B；末字 6 B + 2 pad，`padrem = 12 > 8` ⇒ `lw_ts = 8` ⇒ 尾向量不落本字） + `S_TAIL0 1`（余 4 pad 一次发完，`p0_ts = 4 > 3`） + `S_TAIL1 1`（FCS 尾 + /T/ + 7 个 /I/，`t1_idle = 7`） + `S_IFG 1`（`7+8 = 15 >= 12` ⇒ 1 拍） | **11** | 结构值（无板级锚） |

**C. 订正结论（**有变化，不是"无变化"**）**：

| 项 | 原文（REV2/REV3） | **核后** |
|---|---|---|
| ACK 的 MAC 侧代价 | "MAC 侧 ≈2–4 拍"（并把 TX 引擎的 8 拍与之**相加**成 10–12） | ⭐ **11 拍 —— 是该帧自己的整段线时**；**与 TX 引擎的 8 拍不是相加关系**（8 < 11 ⇒ framer 侧被 MAC 吸收，只要它按时供字） |
| 数据帧的 193 里含什么 | 未写清 | ✅ **已含数据帧自己的全部开销**（前导 1 + pad + 尾字 + IFG 2）—— 由 B 行复现证明 |
| 双向帧周期 | `203 ± 2` | **204 + 气泡(0..2)**（= 193 + 11） |
| 双向载荷带宽 | 8.90–9.08 Gbps | ⭐ **8.86–8.95 Gbps**（`1460/204 = 8.9461`；`/205 = 8.9025`；`/206 = 8.8593`） |

⚠️ **"±2"的口径要改**：原 ±2 来自"framer 8 + MAC 2–4 的估不准"；**核后 ACK 的线时是确定值 11**，不确定的只剩**帧间气泡**（framer 侧 8 拍 < MAC 侧 11 拍 ⇒ 只要控制帧在 IFG 结束前把字送进 MAC 的 16 深字 FIFO 就 0 气泡）⇒ **带子写成 `204 (+0..+2)` 更准，而不是对称的 ±2**。
⚠️ **仍未测**：上述 11 拍**没有板级读数**（ACK 帧的实测帧周期从未单独量过）；且**对端 ACK 交织进板子 RX 流水线**那一半（≈5%，见下条）**不在本预算内**。
- **处置**：① **单向数（9.456）不变**，但它只对"板只发不收"或"对端 delayed-ACK"成立；② 双向目标必须按 **8.86–8.95 Gbps** 立预算（或由 app 层改用 **delayed ACK** 把这一项摊掉）；③ **未独立测量**（Gate C 必须覆盖"ACK 与数据帧交织"的构型）⇒ **不许把 9.456 写成双向可达**。
- ⭐ **REV3 新增（审查二轮 R6③）—— 对称效应，属 Stage B 的边界条件**：上面只算了**板自己 TX 半边**被 ACK 占掉的时间。双向构型里**对端也在发 ACK**（每 ~193 拍插 ~11 拍控制帧进**板子的 RX 流水线**，还要 `tcp_rx` 逐帧处理）⇒ 若 Stage B 的 RX 目标是"逐帧流水占用"模型，**双向档的 RX 侧会比单向档低百分之几**（量级 = 控制帧线时/帧周期 ≈ 11/204 ≈ **5%**）。
  - ⇒ **本设计件必须声明**：§6.1 的 9.456（以及 Stage B 的 RX 目标）**都是"单向/无对端 ACK 交织"口径**；"单路双向 10 Gbps"要按 `min(TX 8.90–9.08, RX 侧扣掉交织后的数)` 立。
  - ⚠️ **未核**：RX 侧的具体数（含/不含交织）不在本件的可读范围内（姊妹设计件的 RX 结构值是 9.76 Gbps；并发的 Stage B 文件在禁碰清单内）⇒ 本条**只给机制与量级，不给裁定**；口径归属 = **Stage B 的边界条件**。

## 9. 结论：**implementation-ready？** + 实施自检清单

### 9.1 一句裁定

> ⭐ **implementation-ready：是 —— 附条件**（"设计面可开工"，**不等于"板级可直接验收"**）。

**条件（缺一不可）**：
1. **S0 先做**：门先建 **+ 在现役 RTL 上打等价变异证明门有牙**（§7.1-S0；范围见 §4.6）—— 门的判别力**未证前，后面所有"绿"都不算数**；

4. **§9.2 的 T1–T12 全过**（下表），其中 **T5/T6/T9 是"会变红"的判据**（不是"跑完没报错"）。
