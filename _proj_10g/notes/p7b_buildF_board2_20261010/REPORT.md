## ① 五行结论

1. ⭐ **`ΔW68 / ΔTcpOutSegs` = `0.999673`（R1A）· `0.999674`（R1B）· `0.999337`（PRE_R1A）** —— W68 比"对端发出的段数"**少 0.033%**；
   用**实测的 ssh 占比**扣掉非测量流量后，本连接口径 = **0.999797 / 0.999747**（即"本连接发出段数 − `ΔW68`" = **+2,899 / +3,094** = **0.0203% / 0.0254%**）。
   ⚠️ **两量语义不同**：`W68` 数的是**推进 `snd_una` 的事件**（板内），`TcpOutSegs` 数的是**对端（纯接收方）发出的段** = ACK + 握手 + FIN ⇒ 比值**不必** = 1；本构型下 ≈1（差 0.02–0.03%）**本身**就是口径被独立确认的读数。
   ⭐ **三角核（最强一条）**：板侧 `ΔW22`（收到并通过 TCP 分类器的帧数）与"对端全系统 `TcpOutSegs` − 实测 ssh" **逐跑吻合到 4 / 6 个数**

## ④ 裁定段（只报读数与边界，**不给 PASS/FAIL**）

### ④-A `L'` 与 `L` 差多少、方向如何 ⇒ `W68` 多计缺口的**界**

- **差值/方向**：三跑全部 `L' < L`，幅度 **0.033% / 0.034% / 0.066%**（由 `ΔTcpOutSegs > ΔW68` 决定）。
- **界（按强度排序）**：
  1. **硬实测**：`ΔW68 < Δ(独立 ACK 计数)` 在 **15/15 跑**成立（净比 0.9985–0.9997）。取 `N_adv ≤ F`（收到的全部 ACK 数，`ΔW22` 与对端口径双证）
     ⇒ **`g = ΔW68 − N_adv ≥ ΔW68 − F = −2,895（R1A）/ −3,088（R1B）`**
     ⇒ ⛔ **"多计"这个方向在本构型连正号都没得到独立支持**；数据同样容得下"**W68 少计 ≤ 0.02%**"。
  2. **上界（条件式，条件明示）**：`g = U − (F − ΔW68)`，`U` = 非推进 ACK 数 ⇒ **`g ≤ U`**。本轮没直接测 `U`，但**三条把 `U` 压小的独立读数**：
     `ΔTcpExtTCPOFOQueue = 0` · `ΔTcpExtTCPACKSkippedSeq = 0` · `ΔTcpExtTCPRcvCollapsed = 0` · `ΔTcpExtTCPFastRetrans = +1`（**R1A/R1B 各 75 GB / 5,137 万帧全程**）
     ⇒ 接收侧**无乱序、无空洞、无 ACK-skipping** ⇒ 不产生 dup-ACK 洪流 ⇒ `U` 只由"尾部 + 窗口更新"构成
     ⇒ **在"尾部/窗口更新 ≤ 与净差同阶"前提下 `g ≤ ~0.03%`**。
  3. **佐证（第三台仪器，同量级）**：`ΔW22 − ΔW68` = **+2,895 / +3,088 / +4,447**（0.0203% / 0.0253% / 0.0402%），与第 1 条净差同量级且各自独立。
- ⛔ **不许写**"直读 ≈ 换算值 ⇒ 互证"（恒等式，上一轮 TL 批注）；也**不许**把第 2 条写成**无条件**结论 —— `U` 未直接测量。
- **换算到 `L`**：0.03% 计数偏差 ⇒ `L` 偏差 ≤ 0.03%，而**同档跨跑 `L` 散布是 0.105–0.187 µs（+78%）** ⇒ **本缺口对 `L` 可用性不构成限制**。
- ⚠️ **对审查轮"W68 多计"的处置**：审查轮登记了**机制上**的两条多计路径（`drain` sticky 被后帧覆盖 · `ack_adv_l` 用 w5 拍的值），
  并据此说"直读 `L` 系统性偏小"。**本轮净计数给出的方向相反**（`ΔW68 < ΔTcpOutSegs`）
  ⇒ 准确口径 = **两条机制仍然存在（未否证），但净差被"对端还发了不推进的段"盖过**；**"L 系统性偏小"这个方向结论在本构型不成立**。

### ④-B 深压档的 `L` 是否落进历史 6–11 µs 带（口径写清）

- **口径**：历史 `L` 是 **µs/窗**；本轮直读是 **µs/事件**；两者**显式换算** `L[µs/窗] = L[µs/事件] × (ΔW68/ΔW20) × (W_eff/1518)`（**不是并列比较**）：

| 档 | W_eff | 事件/帧 | 每窗帧数 | `L`[µs/窗] | 历史带 |
|---|---|---|---|---|---|
| 11680 | 4,380 | 0.7345 | 2.8854 | **8.13**（Q11K）/ **7.83**（Q11KD） | **6–11 ✓** |
| 5840 | 2,920 | 0.7528 | 1.9236 | **9.27**（Q5K）/ **9.38**（Q5KD2） | **6–11 ✓** |
| 2920 | 1,460 | 1.0000 | 0.9618 | **8.61**（Q2K）/ **9.19**（Q2K3） | **6–11 ✓** |
| 基线 | 61,440 | 0.2151–0.2777 | 40.47 | **1.25 / 1.12 / 1.53** | 另一条带 0.9–2.2 ✓ |

- ⇒ **"落进"的口径 = 用 `L[µs/窗]`（显式换算后）比历史带**；三档**全部落进**，跨跑/跨档散布仅 **7.83–9.38（±9%）**。
- ⚠️ **边界**：`W_eff` 取 `W69` 低 16 位众数；tcpdump 档与无 tcpdump 档的 `L[µs/窗]` **分别给出**（7.83 vs 8.13 · 9.38 vs 9.27，差 ≤ 4%，**不能说成 tcpdump 代价**）；**1460 档没有 `L`**。
- ⚠️ ⭐ **历史响应曲线的对齐陷阱**：历史 `W=1,460 → 888 Mbps` vs 本轮 **871 / 814**；历史 `W=2,920 → 1,872` vs 本轮 **1,660 / 1,616** ⇒ 曲线形状复现。
  ⛔ **但历史曲线的 x 轴是"线上窗"、不是 rcvbuf** —— 本轮实测 **rcvbuf → 线上窗 ≈ 整数个 MSS**（11680→4,380=3 MSS · 5840→2,920=2 MSS · 2920→1,460=1 MSS · 1460→832<1 MSS）
  ⇒ **拿 rcvbuf=11680 去对历史的"11,680"是错位对照**（那格要 rcvbuf ≈ 23,360；**本轮未做**）。

### ④-C `ΔW67/ΔW66`（预期 0.0000）

- **11/12 个压窗跑 = 精确 0**（`W67` raw `0x00000000→0x00000000`，跨越 **5 次烧录、12 次跑**）。
- **唯一例外 = Q1KD**（rcvbuf 1460、stall）：`ΔW67 = 2,742,910`、`cap_share = 0.000963`。
  读数归属：该跑 `ΔW66`（2.618e9）几乎全来自 stall 期"无窗可开"，`W67` 只在有数据的几拍里累起
  ⇒ 形态与"流初（对端 SYN 窗 64,240 ⇒ `eff = min(64,240, RING_CAP) = 61,440 = RING_CAP` ⇒ `win_cap_bind=TRUE`）"自洽。
- ⛔ **不许**据此说"板帽在咬"（`W67` 高 = **阈值归属板帽**；这里是 0.1% 瞬态）。

### ④-D ⚠️【本轮新现象】深压块 stall 与内容相位失配（只报读数与边界）

- **stall 读数**（6 跑：Q1K/Q5KD/Q2KD/Q1KD/Q2KD2/Q2K2）：sink 报 `POLL_TIMEOUT 3 x 5000 ms 无数据` 中止；`W68` 只推进 **10–35** 事件；
  板侧 `W69 = (infl 18,980…29,200, eff 0…832)`（**13–20 帧在飞、生效窗塌到 < 1 MSS**）；
  **对端 NIC `Δbytes ≈ 715 KB`（确实收到）而对端 app 只拿到 45 KB** ⇒ **丢在栈内、不在线上**（`nodesc_drops` 计数不动）。
- **分布（读数）**：11680 **2/2 健康**；5840 **2/3 健康**；2920 **2/5 健康**；1460 **0/2** ⇒ **小窗档是"双稳态"**，不是确定性：
  烧录（#4/#5）之后**既有 stall（Q2KD2）也有健康（Q2K3）**。
- **机理 = 推断（未证）**：初突发超过对端接收缓冲 ⇒ 尾部帧被栈丢弃且**无 OFO 事件**（stall 跑 `ΔOFOQueue` 只有 0/+2，健康档 Q11K +196）
  ⇒ 板侧 `win_open` 门（`infl < eff`）在 `infl` 恒 > 微窗（≤832）时**结构性不放行** ⇒ **无 RTO 探询 ⇒ 死锁**。
  ⛔ 需 RTL 级证据才能定案，**本轮不做**。
- **内容相位失配**（1 健康 + 2 stall 跑）：`first_mismatch=0` / `mism_bytes` = 7,968,752,192（Q5KD2）· 45,090（Q2K2）· 53,814（Q1KD）
  ⇒ 形态 = **连接头 ~170–206 B 之后整条流相位错**；三跑**全部紧跟在一次 stall 之后**，且**烧 #5 之后的 Q2K3 内容全清**
  ⇒ 与"上一次 stall 留下的状态"相关（**同槽重连/残留**一族）。⛔ **机理未定**；只登记：**深压块不能假定内容干净**。

## ⑤ 未做到 / 未判定（逐条带原因）

1. **独立分母仍不是"按连接的"**：`/proc/net/snmp` 是全系统口径。本轮用**实测**的 sshd `segs_out` 扣减（**直接测量，非估计**）；
   剩余"其它 TCP"只能来自 3 个空闲 ssh 会话（`estab 3` 不变、背景率 2.6–3.6 段/s）。⚠️ **仍算"未完全隔离"**（扣减项有 ≤1 个采样间隔的不确定度）。
2. **rcvbuf = 1460 档没有 `L`**：连接 stall（10–35 事件）⇒ **不是"没跑"，是"跑了但不流"**；也给不出"W ≤ 832 时的 L"。
3. **2920 / 1460 档拿不到"带 tcpdump 的健康读数"**：带 dump 的 4 跑全部 stall ⇒ **无法做同档对照**；
   只能用"stall 跑里抓到的 win 字段"（1 点/跑）作窗见证 ⇒ 按派单口径**如实写：那两档的"带 tcpdump 读数"含 stall 代价，不可与无 tcpdump 档直接比**。
4. **`U`（非推进 ACK 数）没有直接计数器** ⇒ §④-A 的上界是**条件式**的；**硬结论只有下界**（`g ≥ −0.03%`）。
5. **`W67` 的"满端"（→1.0）仍未撞到**（本批最高 0.000963）。
6. **深压块的 stall/失配只做了"分布"**，没做同会话交替 A/B；`nodesc_drops`/`RcvCollapsed`/`OFOQueue` 在 stall 跑里**都无增量** ⇒ 丢在更隐蔽的一层。
7. **`PRE_R1A`（v1 插桩）无 `Δssh` 见证**（v1 尚未加），只列 `ΔW22−ΔW68`。
8. **未做对端 pcap 全程 ACK 计数**（按派单：**不要**跑全程 pcap）⇒ `W68` 与"线上实抓 ACK 数"的**第三方对照仍缺**（本轮"独立分母" = 对端**内核计数**，不是线上抓包）。
