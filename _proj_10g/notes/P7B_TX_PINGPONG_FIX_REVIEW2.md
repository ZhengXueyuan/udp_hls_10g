## 1. B1 新修法逐项拆（任务最优先）

### 1.1 `fin_cnt==0` 那拍 `f_seq`/`f_plen` 真是寄存器吗？—— **是**（逐行）

| 值 | 现役 TCP 锁存点 | UDP 乒乓模板的 per-bank 同款 | 结论 |
|---|---|---|---|
| 帧基址 `f_seq[b]` | `tcp_tx_frame.v:964` `seq_r <= rb_snd_nxt`（帧首拍，`start_ack||start_data`）；重放 `:842` | 模板 `:254` `id_cap[rx_bank] <= id_r`（帧首拍） | **帧首拍锁存** |
| 帧长 `f_plen[b]` | `:990`（S_IDLE 单拍帧）/`:1016`（S_RECV）`plen_r <= plen_n`（TLAST 拍）；重放 `:852` `plen_r <= plen_preset` | 模板 `:270` `plen_r[rx_bank] <= plen_n`（TLAST 拍） | **TLAST 拍锁存** |

`RX_FIN` 首拍 = T_last+1（转移发生在 T_last 沿；模板 `:274` `rx_state <= RX_FIN; fin_cnt <= 2'd0` 逐字）。⇒ 该拍上两者**都**是寄存器 ✓ —— **不是组合的，B1 修法不塌**。
⚠️ 但修法的成立**依赖实现保住这两个锁存拍**（设计 §1.1-修订自己写了"帧首拍锁存 / TLAST 拍锁存"✓）；若有人把 `f_plen` 放到收尾算，等价性即塌。

**"单拍帧"边角（任务点 2）**：单拍帧的帧首拍 = TLAST 拍 ⇒ `f_seq`/`f_plen` **同一沿落地**，`fin_cnt==0` 拍两者均为寄存器 ✓（设计 §1.1-修订的这句话**成立**）。
- **最短反例（0 长 opener，`tkeep=0`）**：`plen_n = 0 ⇒ 写值 = base+0 = base`（幂等写，与 §3-C5 的处置自洽 ✓）。UDP 模板路径逐字：`:262-275` 的 `tlast` 支在 `tkeep=0` 时 `wr=0`（`:197`）但仍进 `RX_FIN` ✓。
- **1..8 B 帧**：写值 = base+plen ✓ 合法拍上。

## 2. R2 —— B2 的"槽 vs bank"仲裁：字面实现会**重发同一控制帧**

**纸面原文**（§1.4(2)）："TX 引擎在每个帧边界（`T_IDLE` / `T_DONE`）先看 `ctrl_slot_busy` ⇒ 先发控制帧"；同段又说槽"卸载拍 = 该帧 `T_DONE`"。

**缺口**：控制帧**自己的 `T_DONE` 拍**就是一个"帧边界"，而该拍上 `ctrl_slot_busy` **仍为 1**（寄存器在沿上才清）⇒ 按字面规则，引擎**又选控制帧**，而槽里还是同一帧的上下文 ⇒ **同一 FIN/ACK 被发两遍**（`stat_fin/stat_ack` 双计；FIN 侧 = spurious 重复 FIN）。
**更坏的复合**：若此时 `ackq` 还有下一条目且 `rx_idle` 为真 ⇒ 下一拍 `start_ack` 重装槽，而"重发的那个控制帧"正处在 `T_HDR`（`hcnt 0..5` 逐拍读槽，现役 `:1039-1053`）⇒ 帧头由**两代上下文拼出** = **C8 的混拼帧**，而 B2 刚宣布它被关掉了。

**最小轨迹**：`start_ack(T)` 装载槽（busy=1）→ TX 空闲 → `T+1` 起发控制帧（8 拍）→ `T+9` = 该帧 `T_DONE`（busy 沿上才清）→ 边界判定读到 busy=1 ⇒ 重发 → `T+10` 若 `start_ack` 再弹一条 ⇒ 重发帧的 `T_HDR` 中段被换上下文。

**修法**：仲裁键改成"**槽里有未发送的帧**"（例：`start_ack` 置位、控制帧**启动拍**清位的 `ctrl_tx_pend`；或让边界判定用卸载后的值 `busy && !ctrl_tdone`）。**注意 Gate A(i)（`issued_FIN == transmitted_FIN`）能抓重复** ⇒ 这是纸面缺陷、不是门集缺口，但纸上必须写出来（§1.4(2) 现在写的规则**照抄就坏**）。

## 3. R3 —— "无饿死"论证不成立（结论可救）

槽在**每次 `T_DONE` 后一拍**就可被重装（只需 `rx_idle && ack_pend_r && !ackq_empty`），于是"先发槽"能把一个就绪数据 bank 连续压后 **ackq 深度 × 控制帧时长**：最坏 `32 × 8 ≈ 256 拍`（≈1.3 个数据帧期）⇒ **有界、无死锁 ✓**，但 §1.4(2) 的"必然在 ≤1 个数据帧期内排空"**不对**。
- 工程上无碍（条目供给率 = RX 帧率 ≈ 1/190 ≪ 1/8）；
- ⚠️ **TB 注意**：若相位扫描允许 `ack_req` 接近每拍脉冲（ackq 常满），可构造"数据帧无限期推迟"的激励 ⇒ 覆盖见证 `cov_frames` 会不达标 ⇒ **门自己作废（不是假绿）**，这正是 §4.2 见证机制该起的作用；但门的激励设计要么限制 ACK 洪泛概率，要么把这条写进已知陷阱。

## 4. R4 —— 组合校验和**等价性坐实**（任务点 6）

`checksum16.v` 逐行：`:47-49` `init → acc<=init_val(+den?wsum:0)` / `aen → acc<=acc+add_val` / `den → acc<=acc+wsum`；`:51` `fin → csum <= ~fold16(acc)`。`fold16`（`:31-38`）= `f1=v[15:0]+v[31:16]`（≤0x1FFFE）→ `f1[15:0]+f1[16]`（**不会二次进位**）⇒ 对 32 位入参是良定义单次折叠。

控制帧（`tcp_tx_frame.v`）：`csum_init = start_ack`（`:618`，该拍 `den=0`，`:619-620` 要求 `accept`）⇒ `acc = init_val`；随后三拍 `aen`（`:624` `wait_cnt<=2`）依次加 `aen_v1/v2/v3`（`:625-631`）；`fin` 在 `wait_cnt==3`（`:632`）；`wait_cnt==4` 取数（`:1027-1029`）。**全程无 `den`** ⇒ `acc = init_val+v1+v2+v3`（模 2³²）⇒ `~fold16` 一次。
组合树 = `~fold16(init_val+v1+v2+v3)`：32 位加法**结合律** ⇒ **逐位等价 ✓**（任何等价实现都必须"一次折叠、加完再折"，不许边加边折成 16 位 —— 由于 `fold16` 只在末尾调用一次，这条天然满足）。
**半字集合/字节序核对**（`aen_v1/v2/v3` vs 线上头 `:1045-1050`）：伪头 `src_ip×2 + dst_ip×2 + 0x0006 + tcp_len` ✓；`sport,dport,seq_h,seq_l,ack_h,ack_l,doff_flags,wnd` = TCP 20 B 头的全部非零半字 ✓（`csum/urg` 计 0 ✓，与 `w[6]` 的 `tcp_csum` 字段为 0 一致）；`seq_h` 先入 `v1`、`w4` 里也是 `seq[31:16]` 先出 ✓。**唯一实现约束**：组合树必须用与帧头**同拍同源**的 `rb_snd_nxt/rb_rcv_nxt/doff_flags/条目 ack`（`start_ack` 拍），这本来就是设计的写法 ✓。
⇒ 设计 §1.4(3) 的等价性主张**从"纸面推导"升为"已逐位核过"**；Gate A(ii) 仍值得保留（它判的是**实现**，不是这条定理）。

## 5. R5 —— `M-C2` 与 `J_seq_mono`（任务点 7）

- **能不能打出红 = 取决于变异形式**：
  - 形式 A（寄存 `(wr,val,id)` 三件套，"加流水"惯例）⇒ 预留值 `F+1` 滞后 8 拍落地；窗口内**同连接**可发生的更晚写：`aq_syn`（SYN+ACK）不加 `tx_blk`（现役 `:372` 只含 `fin_req|fin_sent_r|rst_sent_r|rst_req`）⇒ 下一拍就能启一个数据帧，它在自己的 `RX_FIN` 首拍写 `base'+plen`（`base'` 读到的还是未预留的 `F`）⇒ 8 拍后预留落地把 `snd_nxt` 从 `F+plen` **拉回 `F+1`** ⇒ `J_seq_mono` **必红** ✓（`J_seq_cont` 也会红）。
  - 形式 B（只延迟 enable、值用落地拍的 `rb_snd_nxt+1` 重算）⇒ 变成**前跳**（`F+plen+1`）⇒ **单调门看不见**（只有窗口账/`retx_hi` 受害）。
  ⇒ 设计必须把变异写死成形式 A（§4.5 现在写的是"加 8 拍延迟"，**欠定**）。
- **"只红 `J_seq_mono`、不红 `$onehot0`"未证**：落地拍若与 `upd_wr_data`/`upd_wr_rew` 同拍（相位扫描下不罕见），`$onehot0` **也**会红 ⇒ "两类门独立"这条正面证据不成立（门本身没问题，只是这条论证据此不能当证据）。

## 7. R7 —— 退路梯第 1 级（"挣余量"）的**新永久丢失**（任务点 4 的第二半）

**现役代码明示的前提**（`:657-661` + `:701-707`）：
- `fin_push = scan_now && fin_req[scan_id] && !fin_sent_r[scan_id] && !ackq_full && (rb_state==1) && (rb_snd_nxt==rb_snd_una)`；
- `ackq_wr = ack_req_ok || fin_push || rst_push || fin_repush || wu_push`，而 `ackq_din` 的优先级是 **`ack_req_ok` 最高** ⇒ 同拍 `ack_req` 到达时，**FIN 条目的数据被 ACK 顶掉**；
- 现役注释逐字："ack_req 优先……FIN 下轮扫描（256 拍）**自动重试**" ⇒ 今天这是**有损但自愈**的已知路径（同批 `fin_repush` 已经用 `fin_repush_ok = fin_repush && !ack_req_ok && !ackq_full`（`:685`）修过同族，**但 `fin_push`/`rst_push` 没修**）。

**"预留提到 enqueue"之后**：预留写（`snd_nxt <= rb_snd_nxt+1`）挂在 `fin_push` 拍发生，而**条目没进队** ⇒ `snd_nxt = F+1 ≠ snd_una = F` ⇒ `fin_push` 的重试守卫 `(rb_snd_nxt==rb_snd_una)` **永久为假** ⇒ **FIN 再无首发路径**（`fin_sent_r` 恒 0 ⇒ `fin_retx_pend` 无入口 ⇒ RTO 重推也无入口）= **F12 的病理原样复活**，只是从"槽被覆盖"换成了"条目被 ack_req 顶掉"。
**RST 更糟**：`rst_push` 的重试条件只查 `!rst_sent_r`（不查 `snd_nxt==snd_una`）⇒ 下轮扫描**重挂 + 二次预留** ⇒ `snd_nxt` 多 +1（永久漂移），且 RST 帧的 seq 语义跟着错。
**另有两处配套义务**（设计只写了半句）：FIN 的 seq 必须改从**条目 `val`** 取（现役 `:964` 对 `start_ack` 无条件 `seq_r <= rb_snd_nxt`，预留后读到的是 `F+1`；`:706` 的 `fin_repush` 填的 `val=32'h0`）——这不是"配套"，是**帧头通路的一处真改**。

**修法**：预留必须挂在 `fin_push_ok = fin_push && !ack_req_ok && !ackq_full`（照抄 `:685` 的 `fin_repush_ok` 先例）；RST 同此。做完这条，退路梯第 1 级才可用。
另外，该级自称"余量 ~256 拍"我判**论证不完整**（若 FIN 的 seq 改从条目取，帧头就不再依赖该 TCB 写；被保护的"下一次帧首拍读"到底是谁没写清）—— 我**没有反例证明它错**，但要求补一句"谁在读、早几拍"。
