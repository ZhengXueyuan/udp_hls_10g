## §1 先把「窗门」的式子读准（源码逐行）

### 1.1 门本体（`rtl/tcb.v`，注册读口）

```
rtl/tcb.v:142   wire [31:0] win_diff = snd_nxt_r[win_id] - snd_una_r[win_id];   // 32 位回绕正确差
rtl/tcb.v:143   wire [15:0] win_cap  = (snd_wnd_r[win_id] < WIN_CAP) ? snd_wnd_r[win_id] : WIN_CAP;
rtl/tcb.v:144-148 always @(posedge clk) begin
                    win_open     <= (win_diff < {16'b0, win_cap});
                    win_inflight <= win_diff[15:0];
                    win_wnd_eff  <= win_cap;           end
```

**【事实】** 三条关键性质（都是读值，不是推断）：

1. **门 = `(snd_nxt − snd_una) < min(snd_wnd, WIN_CAP)`**，三态全部**同沿注册**（`tcb.v:144` 单个
   `always @(posedge clk)`，**无复位**，见 `:132-133` 注释）⇒ `win_open` / `win_inflight` /
   `win_wnd_eff` **是同一个样本的三个投影**（同一 `win_id`、同一拍）。
2. **`win_id` 是外来组合输入**，wrapper 接的是 `rb_id`（`board/wrapper_p4.v:1997`）；
   而 `win_open` 是寄存器输出 ⇒ **第 T 拍的 `win_open` 反映的是第 T−1 拍的 `win_id` 与第 T−1 拍
   的阵列值**（`tcb.v:132-133` 的注释逐字：*"1 拍旧值的影响见 tcp_tx_frame RING_CAP 注释:
   最坏误开 1 拍"*）。
3. **`win_wnd_eff` 就是 `min(snd_wnd, WIN_CAP)` 本身**（不是它的某种变形）⇒ 主机侧**不需要复算 min()**，
   读出来就是那一侧的量。⚠️ 但**它在 `win_wnd_eff == WIN_CAP` 时对「对端恰好给 WIN_CAP」与
   「对端给得更多」不可分辨**（§2.6-裁定①）。

`WIN_CAP` 的**现役取值**：wrapper 以 `.WIN_CAP(WIN_CAP_5)` 传入（`board/wrapper_p4.v:1971`），
`WIN_CAP_5 = 16'hF000 = 61440`（`board/wrapper_p4.v:227`）；同一 `localparam` 也以
`.RING_CAP(WIN_CAP_5)` 进 `tcp_tx_frame`（`board/wrapper_p4.v:2135`）⇒ **两处同源，不会分叉**。

### 1.2 消费点（`rtl/tcp_tx_frame.v`；**现役 = `TCP_TX_OVL` 支**）

**【事实】** 现役构建打开 `TCP_TX_OVL=1`（`board/build_p7b_ku5p.tcl:153`）⇒ **生效的是文件前半支**
（`rtl/tcp_tx_frame.v:451-586` 一带），后半支（`:1305-1431`）是**非现役**的默认/串行支：

| 消费点 | 现役支（OVL） | 非现役支 |
|---|---|---|
| 门线名 | `:458 wire wnd_open = win_open;` | `:1346` 同 |
| 接受门 | `:521-525 s_axis_tready`（S_IDLE 子句含 `wnd_open`） | `:1416-1423` 一带 |
| 启动门 | `:526-529 start_data`（含 `wnd_open`） | `:1421-1423` |
| W66 谓词 | `:581-585 stat_winstall_ev` | `:1429-1431`（注释在 `:1424-1428`，自称**逐字同款**） |
| W66 计数 | `:857 if (stat_winstall_ev) stat_winstall <= …+1` | `:1787` |

**【推演】（= W66 的语义，本件后续全部建立在它上）** `stat_winstall_ev` ⟺
「帧器**站在数据帧启动点**（`rx_state==RX_IDLE && recv_first`）∧ `s_axis_tvalid` ∧
`start_data` 里**除 `wnd_open` 以外**的全部合取项都开 ∧ `!wnd_open`」⇒ 它数的是
**"因为窗口而没能开帧"的拍数**（`:531-585` 的权威注释逐字）。

### 1.3 窗值的来源与量纲（`rtl/tcp_rx.v`）

```
rtl/tcp_rx.v:432   wire [15:0] wnd_f = fend_w6 ? s_axis_tdata[63:48] : wnd_l;   // 线上 16 位窗字段
rtl/tcp_rx.v:436   wire [31:0] wnd_scaled = {16'b0, wnd_f} << ra_wscale;
rtl/tcp_rx.v:437   wire [15:0] wnd_ws    = |wnd_scaled[31:16] ? 16'hFFFF : wnd_scaled[15:0];
rtl/tcp_rx.v:494   pend_wnd_val <= wnd_ws;          // fend 拍锁存
rtl/tcp_rx.v:440-445  upd_sel = (drn==1)?0:(drn==2)?2:4;  // 4 = snd_wnd
```

**【事实】**（这几条是本轮最要紧的量纲链）：

1. `tcb.snd_wnd_r` 里存的是 **`wnd_ws` = 左移 `ra_wscale` 后、饱和在 `0xFFFF` 的值**
   （`tcp_rx.v:437`）⇒ **接出来的任何 `snd_wnd` 都是「缩放后 ∧ 饱和后」的**。
   **不是**线上那个 16 位原值。
2. **本构型下饱和是空操作**：线上真值 = 本构型**没有窗口缩放协商**（SYN 带 `wscale 10`、
   板的 SYN-ACK **不回 WS** ⇒ 对端通告窗被 16 位硬顶 65,535；证据 = 窗口侧轮原件），
   而 `wscale` 落地为 0（行为）⇒ `wnd_scaled == wnd_f ≤ 0xFFFF` ⇒ **`[31:16]` 恒 0 ⇒ 不饱和**。
   ⇒ **当前读到的 `snd_wnd` = 线上原值**，饱和不掩盖任何东西。
3. **饱和会不会掩盖真相**：会 —— 但**只在 `wscale ≥ 1` 的真缩放构型**（那时线上 1000 字节的窗
   会被左移成 1024000 再钳成 65535，主机侧看到的 65535 与「对端真给 65535」不可分辨）。
   ⇒ 要判「饱和有没有发生」不需要一个字：**1 位粘滞够了**（`stat_wnd_sat <= |wnd_scaled[31:16]`，
   1 FF，见 §2.5 可选件）。

**【事实】门的输入是饱和后的值** ⇒ 就「门的哪一侧在咬」这个问题而言，**读饱和后的值是正解**
（门自己用的就是它）；「对端真给了多少」是另一个问题（需要原值 + 饱和位）。

### 1.4 逐拍时间线（写拍 → 可见拍 → 门输出）—— ① 的论证基础

**【事实】** 三个写口来源（wrapper 仲裁 `board/wrapper_p4.v:2017-2033`；**优先级 tx > rx > cfg > fc**）：

| 字段 | 唯一/主要写者 | 出处 |
|---|---|---|
| `snd_una` (sel=2) | **tcp_rx 的 drain**（`tcp_rx.v:443` 的 `drn==2`）+ cfg（ADD 序列 `tcb_idx=2`，`slow_cfg_adp.v:173`） | `tcp_rx.v:440-445`、`slow_cfg_adp.v:156-185` |
| `snd_nxt` (sel=1) | tcp_tx_frame（`tcp_tx_frame.v:500-507`） | — |
| `snd_wnd` (sel=4) | tcp_rx 的 drain（`drn==3`） | `tcp_rx.v:443,494` |
| `rcv_wnd`/`state` (3/5) | app_ctrl 的 fc 通道 | `app_ctrl.v:715-718,727` |

**【推演】「对端 ACK 到家 → 门重开」的逐拍链**（这是设计 I-2/I-3 的锚）：

1. 拍 `F`：ACK 帧的末字被接受，`fend` 有效 ⇒ `pend_una <= ack_adv_l && tcrs`
   （`tcp_rx.v:483,489-492`），`pend_una_val <= ack32_l`；**`snd_una_r` 尚未变**。
2. 拍 `F+1..F+3`：drain FSM 走 `drn` 1→2→3（`tcp_rx.v:501-515`），其中 `drn==2` 且 `upd_gnt`
   那一拍**写入 TCB**（`tcb.v:92`）⇒ 该拍**结束时**阵列变。
3. 拍 `W+1`（`W` = 写拍）：`snd_una_r[·]` 新值对读者可见。
4. 拍 `W+1` 结束沿：`win_open <= (win_diff < win_cap)`（`tcb.v:144-145`）⇒
   **`W+2` 拍门才变**。
5. `W+2` 起：`start_data` / `s_axis_tready` 的 `wnd_open` 项才可能变 1。

⇒ **板内「ACK 到家 → 门重开」的固有延迟 = 从 `fend` 到 `W+2`，约 3–6 拍**（= 0.019–0.038 µs
@156.25 MHz）。**这是结构值，不随负载变**。
⚠️ 另有 drain 与 tx/rx/cfg 写口的仲裁竞争可能再插 1–2 拍（`board/wrapper_p4.v:2017-2033`）。
**【未量】**：确切的拍数没有在板上量过（要量需要带时间戳的仪器，见 §3.3）。
**【事实】** 参照量级：`L` 的现状 = 0.9–11 µs（窗口侧轮）⇒ **板内这段只占 `L` 的 0.2–4%**（【推演】）。

### 1.5 与既有 W63/W64/W65/W66 的关系式（逐条给定义出处）

| 字 | 定义（逐字/逐项） | 域 | 出处 |
|---|---|---|---|
| W63 `app_pattern.stat_frmwait_cyc` | `frm_wait && active && !bad_frm` 拍数 | dp | `rtl/app_pattern.v:1016-1038` |
| W64 `app_pattern.stat_bp_cyc` | `pw_valid && !m_tready && !closing && !bad_frm` 拍数 | dp | `rtl/app_pattern.v:1029-1040` |
| W65 `mac_tx_10g.stat_tx_idle` | `state == S_IDLE` 拍数（**tx 域**） | tx_mii_clk | `_proj_10g/p7b_mac/rtl/mac_tx_10g.v:350` |
| W66 `tcp_tx_frame.stat_winstall` | §1.2 的谓词拍数 | dp | `rtl/tcp_tx_frame.v:581-585,857` |

**【推演】按定义推出来的关系**（不是量出来的）：

- **`W66 ⊆ W64`（逐拍蕴含，允许一个有界的 `ΔH`）**：W66 计数的那一拍 ⇒ 呈交口有字 ⇒
  1 深 `axis_pipe` 满 ⇒ `m_tready = 0` ⇒ app 侧 `pw_valid && !m_tready` 成立 ⇒ W64 那拍也计。
  反向不成立（W64 还含「帧器在忙别的、pipe 满但帧器不在启动点」的拍）。
  ⚠️ 屋里已有的**逐字式子** = `ΔW64 ≥ ΔW66 − ΔH`（`rtl/tcp_tx_frame.v:561-580`，含对 `ΔH` 的登记）。
- **`W66 ∩ W63` = 不同相位**：W63 = 「**本帧已交付完、等 `tx_ok`**」⇒ 那拍 app **还没产出**下一帧的字
  ⇒ `s_axis_tvalid` 结构性可能为 0 ⇒ **W66 那拍结构性不计**。⇒ 两者是**同一次等窗的前后两段**
  （W63 在前、W66 在后、中间夹一段装配/交接），**不是嵌套、也不是互斥**。
- **`W66` 与 `W65` 不是同一件事**：W65 是 **tx 域 MAC FSM 的 S_IDLE 拍**，W66 是 **dp 域帧器启动点的等窗拍**。
  两者**域不同、观测点不同**（中间隔着 `tx_arb`/`u_txcdc`/`mac_tx_10g`）⇒ 比值 `ΔW66/ΔW65` 只是一个
  **聚合近似**（既有读数 0.876/0.899/0.881 = 窗口侧轮）。
  ⚠️ **`W66 ⊆ W65` 不是结构性恒真**（流水线深度与域差都会让两边对不齐）；只可用「同窗比值」口径。

## §2 ① 仪器设计（「把 `L` 拆开」）

### 2.1 目标与「够用」准则

目标是让下面这条式子**每一项都成为独立可读的量**（现状：右边全靠换算）：

```
现状 (窗口侧轮) :  L = (W/1518) × (P − 193)        [拍/窗]      ← W 来自对端 pcap；P ≡ 156.25e6/fps
本设计           :  L = ΔW66 / ΔE                  [拍/次刷新]  ← 两项都在板内、同窗、同域
                    ΔW66 = 帧器因窗口没能开帧的拍数 (已有, W66)
                    ΔE   = 窗口刷新事件次数 (新增)
                    (哪一侧在咬) = ΔW67 / ΔW66      [比值]      ← W67 = 板帽侧的那一份 (新增)
```

**「够用」准则**（本件自己定的验收口径，供下一轮裁）：
① 新字的**分母**能被两条独立口径复现（例如 `ΔE` 与「推进 ACK 数」`ΔE_ack` 在饱和档应一致到几个百分点）；
② `ΔW67 ≤ ΔW66` **逐窗恒成立**（结构蕴含，反了就是实现错）；
③ 新加的 `L` 与旧换算式 `(W/1518)(P−193)` 在**同一跑同一窗**内一致到散布内（旧式是独立路径，
   这正是工程要的**非同源 oracle**）。

### 2.2 I-1：分裂计数器 —— 「对端侧 vs 板帽侧」（**W67**）

- **改哪里**：`rtl/tcp_tx_frame.v`（**单一处**）。**不动 `tcb.v`、不动任何输入端口。**
- **为什么这么便宜（本件最重要的发现）**：`win_wnd_eff` **已经是 `min(snd_wnd, WIN_CAP)`**
  且**已经是本模块的输入端口**（`rtl/tcp_tx_frame.v:103`，注释逐字 *"保留 (debug 走线, 门控不用)"*），
  wrapper 已接（`board/wrapper_p4.v:2179`）⇒ 只需一个比较：
  ```
  wire win_peer_bind = (win_wnd_eff < RING_CAP);        // 与 tcb 用的判据同型 (tcb.v:143)
  ```
  ⇒ **对端侧在咬 ⟺ `win_peer_bind`**；板帽侧在咬 ⟺ `!win_peer_bind`。
  ⚠️ **不必**为此把 `snd_wnd` 接出来、也不必加宽它（派单提示②的实现路径比提示①更省，
  见 §2.6-裁定①）。
- **新增字**：1 个（`stat_winstall_cap`，32 位计数）。
- **语义（逐字）**：
  > `stat_winstall_cap` 在第 T 拍 +1 ⟺ `stat_winstall_ev`（`rtl/tcp_tx_frame.v:581-585`）成立
  > **且** `win_wnd_eff >= RING_CAP`（即 `min(snd_wnd, WIN_CAP) == WIN_CAP`，两侧同沿同源样本）。
  > 它是 **W66 的子集**：`stat_winstall_cap_ev ⇒ stat_winstall_ev`（结构性）。
  > **对端侧拍数 = `ΔW66 − ΔW67`**（不做第二个计数器；省 32 FF）。
- **恒等式/判据**：`ΔW67 ≤ ΔW66`（**逐窗恒真**，负数即实现错，是一条**免费的牙**）；
  `ΔW67/ΔW66` = 「窗口门里由板帽咬掉的那一份」。
- **代价**：1 个 32 位计数器 = **32 FF（dp 域）** + 1 个 16 位比较器（约 2 级 LUT，**输入是寄存器**）
  + 窗口字 1 个（≈96 FF，见 §5.2 的字成本）。
- **碰功能路径吗**：**不碰**。新比较器的唯一消费者是计数器的 CE；计数器的唯一消费者是新输出端口
  → 快照束。**没有任何既有信号的功能被改动**（连 `win_wnd_eff` 都只多一个扇出）。
- **落在哪条锥上**：`win_wnd_eff`（tcb 寄存器输出）→ 16 位比较 → `stat_winstall_cap[*]/CE`。
  现役 WNS 宿是 `u_app/stg_reg[4]/D`（`+0.090` = 周期的 1.41%，见 `P7B_A7_HANDOFF.md`/工程 CLAUDE.md）
  ⇒ **【推演】新锥与它无关**（不同源、不同宿），但**必须实测确认**（§5.3-2）。
- **一个必须写进注释的边界**：`win_wnd_eff == RING_CAP` 的**并列档**被归为「板帽侧」
  （与 `tcb.v:143` 的同一个比较同向）⇒ 对端**恰好**给 61,440 时会被算成板帽侧。
  **结构性偏置 = 至多 1 个字节宽度的一档**，不影响「谁在咬」的判断。

### 2.3 I-2：刷新事件计数器 —— `L` 的分母（**W68**）

**先把「事件怎么定义才不被流水线污染」说清（三个候选，逐个判）**：

| 候选 | 定义 | 被污染的风险 | 裁定 |
|---|---|---|---|
| **E_ack**（**推荐**） | 拍 T：`fend && s_axis_tcrs && ack_adv_l && !fend_trunc` —— 即「**收到一个推进了 `snd_una` 的 ACK**」 | **低**：`conn_id_l` 是**该帧的连接**（不随 `rb_id` 复用而漂）；且谓词**在源码里已经存在**（`rtl/tcp_rx.v:551` 那个分支用的就是它） | **首选** |
| E_gate | `win_open` 的 0→1 沿 | **高**：`win_open` 是**按 `win_id` 复用**的（`tcb.v:142-148` + wrapper `:1997` 接 `rb_id`）⇒ 扫描拍 `rb_id` 会跳到别的槽（`rtl/tcp_tx_frame.v:511-512` 的 mux），而**未配置槽 `snd_wnd=0 ⇒ win_cap=0 ⇒ win_open≡0`** ⇒ 每次「扫描拍撞上活槽」都可能造一个**伪 0→1 沿** | 备选（须加限定，见下） |
| E_block | W66 谓词的 0→1 沿（「进入等窗」） | 中：等待区间内 app 的**字缝**（装配/交接拍）会让谓词掉 0 再回 1 ⇒ **高估次数 ⇒ 低估 `L`**（与 `ΔH` 同族） | 不推荐 |

**E_ack 的逐拍论证**（为什么它干净）：
1. `ack_adv_l` 在 w5 拍算好、`fend` 拍用（`rtl/tcp_rx.v:189,551,657`）⇒ 判据**已是寄存器**，
   新计数器不引入任何新的组合链到既有功能路径；
2. `fend` 拍是本帧的**唯一**收尾拍（`rtl/tcp_rx.v:358`）⇒ 每帧至多 +1，**不会重复计**；
3. `ack_ok` 已经把「ACK 必须落在 `[snd_una, ack_hi]`」的门做掉了（`rtl/tcp_rx.v:300`）⇒
   乱序/陈旧 ACK 不会误计；
4. **已知的边角（如实登记）**：`ack_adv_l` 用的是 w5 拍采样的 `ra_snd_una`，而 TCB 落地要到
   `drn==2` 那拍（§1.4）⇒ 若**另一条 ACK 的 drain 恰在 w5→fend 这段（1–2 拍）内推进了同一连接的
   `snd_una`**，本帧会被**多计一次**（分母略大 ⇒ `L` 略小）。**【未量】**：发生率。
   要**精确**时用变体 E_ack'（见下「精确变体」）。

- **改哪里**：`rtl/tcp_rx.v`（一个 `always` 里的 +1 + 一个**新输出端口**）。
  端口是 **output** ⇒ 既有 TB 例化**不必改**（未连输出合法）；**不得**用 input（那会强制所有 TB 镜像，
  见工程坑 11/坑 24）。
- **新增字**：1 个（32 位计数）。
- **语义（逐字）**：
  > `stat_ack_adv` 在第 T 拍 +1 ⟺ 第 T 拍 `fend && s_axis_tcrs && ack_adv_l && !fend_trunc`。
  > 口径 = **事件数**（不是拍数）；每次 = 「对端发来一个把该连接 `snd_una` 往前推的 ACK」。
  > ⚠️ 与既有 `stat_ack`（`rtl/tcp_rx.v:579`，= **本板要回**的 ACK 数）**完全不是一回事**，读表别混。
- **精确变体 E_ack'（tcb 写口，可选）**：在 `rtl/tcb.v` 的写口加
  `upd_wr && upd_sel==3'd2 && (upd_val != snd_una_r[upd_id])` 计数（32 FF）+ 新输出端口。
  ⇒ 「只数真正改变了阵列的那些写」，杜绝 E_ack 的多计；代价 = 32 位比较器进 TCB 写口那片逻辑
  （**不在功能路径上**，但会比 I-1 更容易碰到布局压力）。**【需综合】**两者取一。
- **代价**：1 个 32 位计数器 = **32 FF（dp 域）** + 1 个新 output 端口 + 窗口字 1 个（≈96 FF）。
- **碰功能路径吗**：**不碰**（谓词是既有寄存器 + 计数器不回喂任何功能逻辑）。
- **落在哪条锥上**：`fend`/`s_axis_tcrs`/`ack_adv_l`/`fend_trunc` → 计数器 CE（4 个寄存器输出，
  ≈1–2 级 LUT）⇒ 与 W66 同族**风险等级**（W66 已经这么接了）。

**E_gate 的备选设计（若要它与 E_ack 互为见证）**：
- 限定式：`stat_refresh_ev = win_open && !win_open_d && win_qual_d`，其中
  ```
  win_qual     = (rx_state == RX_IDLE) && !svc && !ring_eval && !scan_now && !rx_flush; // = rb_id 指向 start_id 的那些拍
  win_qual_d   = 1 拍延迟（因为 win_open 本身晚 1 拍，§1.1-2）
  ```
  ⇒ **必须延迟 1 拍**，否则限定条件与样本错位、污染原样进来（**这是本条的要点**）。
- 代价：2 FF + 32 位计数器 + 窗口字。**先做零构建的污染量体检**（见 §5.3-3）。
- ⚠️ 若**不做限定**直接数 `win_open` 的沿 ⇒ 本件判**不可用**（污染机理见上表）。

### 2.4 I-3：阻塞点的窗状态锁存（**W69**，可选但强烈建议）

动机：I-1/I-2 给的是**比值与次数**；要判「当时到底差多少」还缺**操作点**（in-flight 与有效窗的绝对值）。
派单提示①要的东西（`snd_wnd` / `min()`）在这里以一个**锁存字**的形式一次拿全。

- **改哪里**：`rtl/tcp_tx_frame.v`（把两个**已有输入** `win_inflight`/`win_wnd_eff` 在
  `stat_winstall_ev` 拍锁存 + 一个新 output）+ 快照接线。
- **新增字**：1 个（`o_win_at_winstall`，32 位 = `{win_inflight[15:0], win_wnd_eff[15:0]}`）。
- **语义（逐字）**：
  > 在第 T 拍，若 `stat_winstall_ev` 成立，则 `o_win_at_winstall <= {win_inflight, win_wnd_eff}`
  > （**同沿同源样本**，与那次阻塞判据用的是同一份）；否则保持。
  > ⇒ 它是「**最近一次因窗口而没开成帧**那一刻的（在飞, 有效窗）」。
  > 新鲜度判据：同窗 `ΔW66 > 0` ⇒ 本窗内至少发生过一次 ⇒ 该字属于本窗；`ΔW66 == 0` ⇒ 陈旧值，**不许读**。
- **代价**：32 FF（dp）+ 1 个 output 端口 + 窗口字 1 个（≈96 FF）；`stat_winstall_ev` 的**扇出 +32 CE**
  （它已经在驱动 W66 的 CE 与（若采纳）W67 的 CE）。
- **碰功能路径吗**：**不碰**（锁存的 D 是寄存器，CE 是既有信号）。
- **落在哪条锥上**：`stat_winstall_ev` 那条宽组合锥 → CE。**同一条锥已经在驱动 W66**，
  本件只是加扇出 ⇒ 风险等级与 W66 同，**【需综合】**确认扇出没把它推成新最差。
- **它替掉了什么**：窗口侧轮的 `W`（线上窗）是**从对端 pcap 读的**（`p7b_window_side_20261010/runs/DP_*_dump.txt`
  的 `mid-flow win` 字段，= **对端通告窗**）—— 本字把它换成**板内直读**，且口径是**门真正用的那个 `min()`**。

### 2.6 对派单三条强提示的裁定（含否掉的理由）

**裁定①（提示 1「把 `snd_wnd` 接进快照」）= 部分采纳，改走更省的等价路径。**
- 采纳的部分：**「哪一侧在咬」必须变成直接读数** —— 这条判断完全正确，本件用 I-1（`win_wnd_eff` 的
  比较）+ I-3（锁存字）实现。
- **改掉的部分（理由）**：**不必**把「缩放的 `snd_wnd`」当新端口接出来：
  ① `win_wnd_eff` **就是** `min(snd_wnd, WIN_CAP)`（`tcb.v:143`），门判据用的也正是它；
  ② 接 `snd_wnd` 本身要**改 `tcb.v` 的注册口**（16 FF + 端口面）；而 `win_wnd_eff` 是**已有端口**
  （`tcp_tx_frame.v:103`）；
  ③ 量纲上 `snd_wnd` 只在**并列档/饱和档**多给信息（`A17` 要的 `L` 与「谁在咬」都不需要它）。
  ⇒ 结论：**先不加 `snd_wnd` 字**；若将来要答 `A18` 的「板看到的对端窗 = pcap 看到的窗吗」，
  再加（配方：`tcb.v` 在同一条注册 `always` 里加 `output reg [15:0] win_wnd_raw`，16 FF，
  ⚠️ 语义 = **缩放后 ∧ 饱和后**的值，逐字写进注释）。
- **关于饱和的明确回答（派单点名问的）**：**接出来（无论走哪条路）的都是「缩放后 ∧ 饱和后」的值**；
  本构型 `wscale = 0` ⇒ 不饱和 ⇒ 与线上原值逐位相同（§1.3-2/3）。

**裁定②（提示 2「把 W66 按 `min()` 的哪一侧劈开」）= 采纳，且用「一个计数器 + 减法」。**
- 理由：`win_peer_bind` 只需要一个**已有的 16 位比较同型式**（`win_wnd_eff < RING_CAP`），
  不需要新的注册口；**只加板帽侧那一个计数器**（`Δ对端 = ΔW66 − ΔW67`）省 32 FF，
  且 `ΔW67 ≤ ΔW66` 是一条**免费的结构性牙**。

**裁定③（提示 3「窗刷新事件计数器」）= 采纳，但事件选 `E_ack`（`snd_una` 前进）而不是 gate 侧。**
- 理由：`snd_una` 前进的谓词**在源码里已经算好**（`rtl/tcp_rx.v:551`），且**按 `conn_id_l` 天然不分槽**
  ⇒ 没有 `win_id` 复用污染（§2.3 表格）；而 gate 侧（`win_open` 沿）**必须**加 1 拍延迟的限定，
  否则被扫描拍污染 —— 派单提示里那句「`win_open` 是注册输出、这条链上本来就有 1 拍陈旧」正是这个坑，
  但它只在**限定条件也同拍延迟**时才被正确处理。
- 附带结论（**本件的正面产物**）：`L = ΔW66/ΔE_ack` 里的**分子与分母都测在帧器/接收侧**，
  不再依赖对端 pcap 的 `W`，也不再依赖 `P ≡ 156.25e6/fps` 的换算 ⇒ **`L` 从「换算量」变成「两个计数器之比」**。

## §3 ② 「答不了」的边界（逐条判）

### 3.1 `L` 的子成分：板侧能不能分开？

| 子成分 | 板侧能分吗 | 为什么 / 需要什么才能分 |
|---|---|---|
| **板内「ACK 到家 → 门重开」延迟** | **能（结构上界）** | 由源码逐拍推得 = 3–6 拍（§1.4）⇒ 占 `L` 的 **0.2–4%**。**这是【推演】，不是测量**：要实测需带时间戳的仪器（见 §3.3） |
| **板 TX 线排队** | **能，且它本就不在 `L` 里** | `L` 的口径是**帧器启动点**（W66，`rtl/tcp_tx_frame.v:581-585`），下游 `tx_arb → u_txcdc → mac_tx_10g` 的拥塞**不进 W66**（帧启动门里没有 `m_axis_tready` 项）⇒ 线排队只会延迟「刷新的效果」，不会成为 `L` 的一项。板侧独立可读：W65（线空闲）、W29（DP 有字下游不收，`board/wrapper_p4.v:3408`）、W28（`u_txcdc` 占用峰值） |
| **对端 ACK 节奏（到达间隔）** | **能测「结果」，不能测「原因」** | 到达间隔可由 `ΔE_ack` 与时间窗算出（**本件已给**）；但「对端为什么这时候 ACK」需要 pcap 时序 + 对端 `ss -ti` 的 `delivery_rate`/`rcv_space` + 对端 app 读节奏（`strace`/采样） |
| **RTT 里的排队** | **不能** | 板上**没有**任何逐段的时间戳/回环时刻 ⇒ 无法从 `L` 里剥出「链路/对端栈排队」那一份。需对端 `ss -ti` 的 `rtt`/`rttvar`/`minrtt` 或**两端 pcap 的成对时序** |
| **对端读取（peer app）** | **只能间接（靠窗的哪一侧）** | `I-1` 的 `ΔW67/ΔW66` 能分出「对端侧在咬」（对端 app/缓冲是瓶颈）vs「板帽在咬」；但**不能**再分「对端 app 慢」vs「对端栈慢」 |

### 3.2 结论：板侧**结构上分不开**的部分（明说）

- **`L` 的「对端+链路」那一段内部，板侧分不开**。板上唯一能给的边界是：
  ① 板内固有延迟是**结构常量**（§1.4，3–6 拍）；
  ② `L` 的总量可**直接测**（§2.3）；
  ③ 瓶颈在**哪一侧**可**直接测**（§2.2）。
- **板上能给的最强结论**（建议作为下一轮的收口口径）：
  > 「`L` = X 拍/次刷新（直测，区间 [a,b]），其中板内结构性最多贡献 k 拍（≤4%）；
  > X 的**绝对多数**发生在「对端尚未发出推进 ACK」的那一段 —— 是**对端+链路**，不是板内串行化。
  > 板侧**不再细分**（对端栈 / 对端 app / 链路排队三者不可分）。」
- ⚠️ **不许把「板内延迟小」写成「对端慢是已证」** —— 前者只把「板内不是主要项」证到 `1 − k/L` 的精度，
  剩下的是「非板内」，其中还包括**链路 RTT**（不属于「对端慢」）。

### 3.3 需要什么才能分（清单，逐条写「要哪个字段/哪个量」）

1. **对端 `ss -ti`** 的 `rtt` / `rttvar` / `minrtt` / `rcv_wnd` / `rcv_space` / `delivery_rate` /
   `pacing_rate`（口径：**同跑同窗取**）⇒ 能把「RTT 里的排队」与「对端窗口/缓冲」分开；
2. **两端 pcap 的成对时序**（板发帧时刻 ↔ 对端 ACK 时刻）⇒ 能给 RTT 与「对端栈延迟」的上界；
3. **对端 CPU/软中断采样**（`mpstat -P ALL 1` / `/proc/softirq` 前后差 / sink 进程绑核见证）
   ⇒ 能判「对端掉队跑」（既有 `A11` 的缺口，同族）；
4. **板上若要再进一步**：需要一个**逐段的时间戳仪器**（在 `tcp_tx_frame` 记「本帧首字上线拍」、
   在 `tcp_rx` 记「该 ACK 覆盖的 seq 对应的发送拍」）⇒ **这不是 1–2 个字能做的**，
   要一份**专用设计**（本件不做，只登记为「若要，得单列」）。

```
rtl/tcp_rx.v:283   wire seq_eq = (seq32 == ra_rcv_nxt);
rtl/tcp_rx.v:284   wire seq_lt = (seq32 < ra_rcv_nxt);   // 重复/旧段 (回绕安全: 无符号比较)
rtl/tcp_rx.v:313-314  wire w6a_ok = base_ok && (plen_w == 16'd0) &&
                                   ((seq_diff <= {16'b0, ra_rcv_wnd}) || seq_lt);
```
两个消费者：`w6a_ok`（`:313`）与 `ackresp`（`:326-327`，`(!seq_eq && (win_ok || seq_lt))`）。
⚠️ 派单写的 `:307-308` 是**注释块**（`:306-312`），**代码在 `:313-314`**。

**【事实】为什么危险（不是"注释错"而是判据错）**：`seq_lt` 是**无符号绝对比较** ⇒ 回卷后
「回卷前的旧段」（数值大、逻辑上旧）会被判成「**远超前段**」⇒ 按 `:320-325` 的既有语义
（*"远超前段 (!seq_eq && !win_ok && !seq_lt) 仍不回 ACK"*）⇒ **静默不回 ACK**（`A8` 逐字后果）。

**最小改法（RFC 的相对比较）**：
```verilog
// 现在 (rtl/tcp_rx.v:284)
wire seq_lt = (seq32 < ra_rcv_nxt);                 // 绝对比较
// 改为 (RFC 793 的 SEQ_LT 语义: 有符号解释 (a-b))
wire seq_lt = seq_diff[31] && (seq_diff != 32'd0);  // = $signed(seq32-ra_rcv_nxt) < 0
```
- `seq_diff` **已经存在**（`rtl/tcp_rx.v:275`）⇒ **不新增任何宽运算**，且**删掉一个 32 位比较器**
  （净 LUT **下降**）。⚠️ `(seq_diff != 32'd0)` 这一项在 `seq_diff==0` 时（即 `seq_eq`）本来
  就被两个消费者排除（`ackresp` 有 `!seq_eq`；`w6a_ok` 的 `seq_diff <= ra_rcv_wnd` 恒真）
  ⇒ **保留它只是为了语义自明**，删掉也可（两种写法在**消费者层面逐位等价**，【需仿真】确认）。

**【推演】「正常（不回卷）工况下逐位不变」的论证（给严格的等价域）**：
- 设 `d = (seq32 − ra_rcv_nxt) mod 2^32`。两个定义：
  - 旧 `A = (seq32 < ra_rcv_nxt)`（无符号）；
  - 新 `B = (d ≥ 2^31) && (d ≠ 0)`。
- **命题**：若 `|seq32 − ra_rcv_nxt| < 2^31`（把两者当**普通整数**做差的绝对值），则 `A ≡ B`。
  **证明**：若 `seq32 < rcv_nxt` 则 `seq32 − rcv_nxt ∈ (−2^31, 0)` ⇒ `d = 2^32 + (seq32−rcv_nxt)
  ∈ (2^31, 2^32)` ⇒ `B` 真，`A` 真 ✓；若 `seq32 > rcv_nxt` 则差 `∈ (0, 2^31)` ⇒ `d < 2^31` ⇒
  `B` 假，`A` 假 ✓。∎
- ⇒ **等价域 = 「`seq32` 与 `rcv_nxt` 的数值差 < 2^31」**。而「本连接尚未跨过 32 位回卷」正是它的
  充分条件（回卷前两者都在同一"半空间"里，且合法流量永远落在窗口内 ⇒ 差 ≤ 64 KB ≪ 2^31）。
- **差异只出现在两种输入上**（这是**必须如实登记**的部分，不许写成"完全不改行为"）：
  ① **跨 32 位回卷后的旧段**（数值差 ≥ 2^31；= 本修复的目标，旧码静默、新码回 ACK —— **RFC 合规**）；
  ② **数值上离 `rcv_nxt` ≥ 2 GiB 的畸形/伪造 seq**（新码现在会给它回一个 ACK，旧码静默；
     RFC 793 本来就要求对不可接受的段回 ACK，RFC 5961 收紧了这条，**两种都算合规**）。
- **两条硬要求**（不许省）：
  1. **判据**：TB 注入「回卷后的旧段（seq = 回卷前一个值）」⇒ 期望**线上出现 ACK**；
     **负对照 = 现役 RTL**，期望**零 ACK**（这条是"有牙"的证明；零构建，xsim 可做）。
  2. **搭车订正注释**：`rtl/tcp_rx.v:284` 的 *"回绕安全: 无符号比较"* **措辞过宽**，改成
     逐字说明等价域与两种例外（见上）。⚠️ 纯注释改动**零网表差异**，但会**改文件哈希** ⇒ 走
     「搭下一次构建」的既有惯例（`P7B_OPEN_ITEMS.md` `A8`-④ 已登记该动作）。
- **代价**：净 LUT **↓**（删一个 32 位无符号比较、加一个 1 位 AND + 一个 31 位 OR-归约）；
  **【需综合】** 后者是宽归约，实际 LUT 数待测（很可能仍是净减）。
- **落在哪条锥上**：`seq_diff`（既有）→ 1 位 → `w6a_ok`/`ackresp` → `fend_w6a`/`ack_req` 等
  **rx 侧功能路径**。⚠️ 这是一条**真功能路径**（不是观测）⇒ 改完必须**整链门 + STA**。
  现役 WNS 宿在 app 侧（`u_app/stg_reg[4]/D`）⇒ 【推演】不撞 WNS，但**必须实测**。

### 4.2 `#17`（`F-3`）：MMCM 失锁重锁 ⇒ DP 侧帧中重启（`B6`）

**【事实】现状与既有实测（这一步必须先读，否则会做出一个已被证伪的方案）**：
- 复位链路：`clk_gen_p6b` 的 `rst_async = (~locked_raw) | rst_ext`、4 拍同步释放、`rst_dp` 高有效
  （`rtl/clk_gen_p6b.v:228-237`）；wrapper 取反成 `dp_rst_n`（`board/wrapper_p4.v:696-716`）。
- 两个 CDC FIFO **两侧复位都接板级 `reset_n`**（不是 `dp_rst_n`）：`u_rxcdc`
  （`board/wrapper_p4.v:891-905`，逐行 `.wr_rst_n(reset_n)` / `.rd_rst_n(reset_n)`）、
  `u_txcdc`（`board/wrapper_p4.v:2748-2760` 同款）。
- **⭐ 已有实测（决定性）**：`P6B_CDC_AUDIT.md` §A.3（`:175-190`）用三个变体做过链上实验：
  **A 现行 / B 只复位读侧（= 字面建议）/ C 两侧同源同拍复位** —— **三种都会**在重启后交付一个
  **帧中截断的片段，且携带原帧 `tcrs=1`**（= 被当 FCS 有效帧交付）；**B 还额外违反 FIFO 复位契约
  （`stale_words=26`，把已消费的整帧重投）** ⇒ **字面建议必须不做**。
  根因（原件逐字）：**「DP 侧没有以 SOP 为界的重启重同步」（FIFO 无法提供帧对齐信息）**。

⇒ **本件的设计据此改向**：不动 FIFO 复位、不动 `rst_dp` 的极性/来源，而是**给 DP 侧加一个
「重启后等 SOP 再开帧」的入口门**，由**事件脉冲**驱动。

- **最小改法（分两处，都在既有观测/复位面之外，不动功能值）**：
  1. **脉冲源（3 FF，零新 CDC）**：`locked` 的 DP 域同步链**已经存在** ——
     `board/wrapper_p4.v:3300-3301` 的 `mmcm_locked_sr_dp`（`:3417` 在 `dp_clk`/`dp_rst_n` 域里移位）。
     加 1 个延迟位 + 1 个 AND：
     ```
     mmcm_locked_d <= mmcm_locked_sr_dp[1];
     wire relock_evt = mmcm_locked_sr_dp[1] & ~mmcm_locked_d;   // dp 域 1 拍脉冲
     ```
     **为什么它一定在每次重启后恰好来一次**【推演】：该链被 `dp_rst_n` 清 0（`:3399`），
     复位期间被钉在 0；释放后 `locked=1` 逐拍移入 ⇒ `[1]` 必然出现一次 0→1 ⇒ 脉冲必发一次
     （**这正是"事件脉冲清"要的确定性**）。**【需仿真】** 核 `SIM_BYPASS` 的锁模型
     （`rtl/clk_gen_p6b.v:157-166`）在同一激励下给同样的序列。
  2. **消费者（入口门，DP 域）**：在 DP 侧**第一个**消费者加一个「丢弃直到下一个 SOP」的门：
     现役入口 = `vlan_strip`（`board/wrapper_p4.v:934` 例化；它的 `S_PASS` 支是**无条件直通**，
     `rtl/vlan_strip.v:170-171`，这正是片段能透过去的原因）。
     设计：
     ```
     reg resync_hold;                       // 1 FF
     always @(posedge dp_clk or negedge dp_rst_n)
       if (!dp_rst_n)                        resync_hold <= 1'b0;
       else if (relock_evt)                  resync_hold <= 1'b1;
       else if (s_axis_tvalid && s_axis_tuser) resync_hold <= 1'b0;   // 见到 SOP 才放行
     // 输出侧: m_axis_tvalid = resync_hold ? 1'b0 : <原式>；输入照常吞 (tready 不阻塞上游)
     ```
     **为什么它不引入新的 CDC 问题**：`relock_evt` 是 **DP 域内**的脉冲（源 = dp 域同步链，
     见 1）；`resync_hold` 与它的消费者全在 `dp_clk` 域；**FIFO 两侧复位一字未动**（保持
     `P6B_SPEC §4.4` 的"指针同代"硬契约）⇒ **没有新增任何跨域路径**。
     **为什么它"不改行为"（正常工况下）**：`relock_evt ≡ 0`（正常工况无失锁）⇒ 门恒选原式 ⇒
     **逐位等价**；唯一的**代价**是输出 `m_axis_tvalid` 上多 1 级 LUT（**需 STA**）。
- **代价**：1 FF（延迟）+ 1 AND（脉冲）+ 1 FF（hold）+ 输出 valid 上的 1 级 mux。
  ⚠️ **不覆盖 100%**：门只保证「重启后第一帧从 SOP 开始」，**不能**修「重启前已进 FIFO 的半帧
  + 重启后到达的剩余字」被拼成一帧的情形（那是 FIFO 内容语义，不是入口门能管的）⇒ 这条**必须
  写进残余**（与 `P6B_CDC_AUDIT.md` §A.3 一致：原件也说了"根因在 DP 侧无 SOP 重同步"，
  但它的三个变体都只覆盖了"重启后首帧"这一半）。
- **【需仿真】**：用 `audit_scratch/t9_f3restart/tb_f3_restart.v` 的模板（同上 §A.3）跑
  A/B（HEAD vs 新门）⇒ 判据 = 「重启后首个交付帧必须带 `tuser`（= 完整帧首）**或整帧丢弃**」，
  且**带 `tcrs=1` 的截断片段数 = 0**（HEAD 期望 1 ⇒ 有牙）。

### 4.3 `#18` = `_proj_mdio/rtl/mdio_master.v` 两个潜伏项（`B7`）

**【事实】源码位置**：
```
_proj_mdio/rtl/mdio_master.v:29   input wire start,   // 1-cycle pulse; ignored while busy   ← 静默丢弃
_proj_mdio/rtl/mdio_master.v:36   output reg done_sticky,  // held until the next start     ← 报上一次结果
_proj_mdio/rtl/mdio_master.v:52   wire tick = (div_cnt == DIV[15:0] - 16'd1);   ← 16 位截断
_proj_mdio/rtl/mdio_master.v:24   parameter integer DIV = 25
_proj_mdio/rtl/mdio_master.v:49   reg [15:0] div_cnt;
```
`DIV = 65537 ⇒ DIV[15:0] = 1 ⇒ tick 每拍都成立 ⇒ MDC = clk/2 = 50 MHz`（`../CLAUDE.md`「已知的潜伏项」逐字。

**(a) `busy` 期 `start` 静默丢弃** —— 最小改法（**只加观测，不改事务机**）：
```verilog
output wire        ready,          // = ~busy：把"能不能发"变成可判（新增 output，既有 TB 不受影响）
output reg  [31:0] stat_start_lost // 在 start && busy 那一拍 +1
...
assign ready = ~busy;
always @(posedge clk) if (start && busy) stat_start_lost <= stat_start_lost + 32'd1;
```
- **为什么这是最小且安全的**：事务 FSM 的**赋值一字未动** ⇒ 合法用法（等 `done` 再发下一次）
  **逐位不变**；新增的两条都是**纯观测**（`ready` 是 `busy` 的反相，不产生新状态）。
- **为什么不建议"把 `start` 挂起"**：那要锁存 `op/phyad/regad/wr_data`（28 位）+ 排队语义
  （覆盖还是排队？）⇒ 把"读时钟工具"变成一个有状态机 ⇒ 收益（省一次重发）远小于风险。
- ⚠️ **`done_sticky` 的语义不要改**（它"保持到下次 start"是**刻意的 VIO 轮询设计**，`:36` 注释逐字）；
  与静默丢弃叠加才有害 —— 修法是让**丢弃可见**（`stat_start_lost`），不是改 `done_sticky`。

**(b) `DIV[15:0]` 静默截断** —— 最小改法（**合法参数下逐位不变；非法参数下由静默变响亮**）：
```verilog
localparam integer DIV_M1 = DIV - 1;
wire         div_ok  = (DIV >= 2) && (DIV_M1 <= 65535);   // 常量: 综合期即定
wire         tick    = div_ok && (div_cnt == DIV_M1[15:0]);
output wire  param_bad;                                   // = ~div_ok: 送 VIO 探针 (常量, 零逻辑)
assign param_bad = ~div_ok;
```
- **逐位不变的证明（合法域 `DIV ∈ [2, 65536]`）**：`DIV ≤ 65535 ⇒ DIV[15:0] == DIV` 且
  `DIV_M1 == DIV−1` ⇒ 原式 `div_cnt == DIV[15:0]−1` **= 新式** ✓；`DIV == 65536 ⇒ DIV[15:0] == 0`
  ⇒ 原式比较 `65535`，新式 `DIV_M1 == 65535` ⇒ **同值** ✓。⇒ **`[2, 65536]` 全域逐位等价**。
- **非法域的取舍（要写进注释）**：`DIV ≥ 65537` ⇒ `tick ≡ 0` ⇒ **MDC 不再跑**、`busy` 起来后
  **永不 `done`**（= 响亮失败：主机的等待会超时，而不是拿到一个 65,536× 快的时钟下读出的"貌似正常"的值）。
  `DIV ≤ 1` 同理（`DIV=1` 原本给 50 MHz，是**违反 802.3 的 MDC 上限**）。
- ⚠️ **另一条可选路（需先验证工具支持）**：在 `initial` 块里 `$error/$fatal` 做**综合期硬失败**。
  **【需仿真/综合】** Vivado 2025.2 是否在 elaboration 期支持该用法（跑一次带 `DIV=70000` 的综合，
  看是 `Fatal` 还是静默放过）。**不许在没验证前把它写成"编译期报错"**。
- **代价**：`div_ok`/`param_bad` 是常量（0 LUT）；`tick` 多一个 AND（**注意**：`tick` 是**功能路径**
  —— MDC 的时钟门，改它属于动功能，必须走 `_proj_mdio` 的 TB `tb/tb_mdio_master.v`（12 项检查）
  + 一次重建位流（"不能只加 `ram_style`"那类教训的反面：**小改动也要重建**）。
- **【需仿真】**：TB 加 3 条（`start && busy` ⇒ `stat_start_lost` 恰 +1；`ready == ~busy`；
  `DIV=65537` ⇒ `tick ≡ 0` 且 `param_bad=1`）。
- ⚠️ **`_proj_mdio` 是独立工程**（自带 `build_mdio.tcl` / `probe_phy.tcl`，在 `D:\repo\XCKU5PMini\_proj_mdio\`，
  **不在 `udp_hls_10g` 仓内**）⇒ 与 10G 位流无任何交互（§5.1）。
