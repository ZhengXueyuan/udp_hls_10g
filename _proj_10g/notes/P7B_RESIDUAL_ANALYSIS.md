## 1. 残差 ①：`W29`/`W45` ≈900/s

### 1.1 先把派单里的两个前提逐字核掉

**(A) "两计数器增量逐字相同" —— 核实结果：成立，而且比"增量相同"更强：绝对读数逐位相同。**

【事实】`_proj_10g/notes/p7b_udp_longrun_20261009/tables.txt:16-17`（L1 窗，raw）：

```
   W45  txcdc_ovf_cnt          A=0x00021ff8 B=0x00063a2f Δ(raw)=268855 ⚠️非0
   W29  txwire_stall_cycles    A=0x00021ff8 B=0x00063a2f Δ(raw)=268855 ⚠️非0
```

【事实】同一跑里**三个快照**（`log_L1.txt:135/151`、`:3829/3845`、`:3987/4003`）逐对核对，W29 与 W45 **每一对都是同一个十六进制数**（`0x00021ff8` / `0x00063a2f` / `0x00067a01`）；L2（`log_L2.txt:134/150`、`:948/964`、`:1106/1122`）与 D2（`log_D2.txt:132/148`、`:346/362`、`:502/518`）同样逐对相同。

**(B) 派单给的数对错了 —— 是 L1 与 L2 混了。**【事实】
- L1（300.0141 s）：W29 与 W45 **各自** +268,855 ⇒ **896.1/s**；
- L2（60.0309 s）：W29 与 W45 **各自** +54,730 ⇒ **911.7/s**。
- 派单里的"W29 +268,855、W45 +54,730"是两个不同**跑**的数，不是同跑两个计数器。

### 1.2 源码级定案：两计数器数的是**同一条谓词**（所以恒等 = 同义反复）

【事实】`board/wrapper_p4.v`：
- `:2734-2742` 例化 `fifo_async #(.WIDTH(73), .DEPTH(256), .FWFT(1), .AW(8)) u_txcdc`，`.wr_clk(dp_clk)`、`.wr_en(txsrc_tvalid)`、`.full(tx_fifo_full)`、`.ovf_cnt(txcdc_ovf_cnt)`；
- `:2743` `assign txsrc_tready = ~tx_fifo_full;`
- `:3365`（`always @(posedge dp_clk)`）`if (txsrc_tvalid && !txsrc_tready) txwire_stall_cycles <= txwire_stall_cycles + 32'd1;`

【事实】`rtl/fifo_async.v`：`:184` `wr_ok = wr_en && !full_r`；`:191` `ovf_pulse_w = wr_en && full_r`；`:212` `if (ovf_pulse_w) ovf_cnt <= ovf_cnt + 32'd1;`

⇒ 把 `txsrc_tready = ~tx_fifo_full` 代入 W29 的判据，W29 与 W45 的加一条件**逐字等价**：`txsrc_tvalid && full_r`；两者**同一时钟**（`wr_clk = dp_clk`）、都是每拍 +1。
⇒ 【推断，结论很硬】`W29 ≡ W45` 是**结构性恒等**，二者读数**不构成两条独立证据**。

⚠️ **复位口径的一条精度补充**【事实】：两者的复位**不是同一根线** —— W29 用 `dp_rst_n`（`wrapper_p4.v:715`，= clk_gen_p6b 的 `dp_rst_dp` 反相、含 MMCM 锁定门），W45 用 FIFO 的 `wr_rst_n = reset_n`（`:2734`；`rtl/fifo_async.v:161-165` 在写域两级同步释放。**这是设计纪律**：FIFO 两侧指针必须同代复位，见 `wrapper_p4.v:684-686` 的硬规则）。⇒ 两者在**板级复位**上一起清零（W45 晚 ~2 个 dp 拍），但若 **`dp_rst_n` 在中途重断言（MMCM 失锁重锁）而 `reset_n` 不跟**，两数会**永久分叉**。**8 个窗口 / 5 个会话（含 300 s）从未分叉** ⇒ 顺带也是一条"本批跑的窗内 MMCM 没有掉锁重锁"的正面证据（登记，不夸大为判据）。

⚠️ **由此订正一条已入库引用的论证强度**：`_proj_10g/notes/P7B_W9_GAP_VERIFY.md:329`（表行 #17）写着
「板级读数印证：RATE 窗 `ΔW45 = +2274 = ΔW29`，是"被拒但重试"的拍数，**不是丢字**」。
- 该句的**语义结论（被拒但重试、不是丢字）本轮不推翻** —— 它另有支撑：AXIS 合同下 `tx_arb` 在 `!tready` 时保持数据（`rtl/tx_arb.v:29-34`：`m_axis_tdata/tvalid` 由 `sel_fast` 组合选择、有效期内不撤销），且**板上内容判据**（L1/L2 每跑 3000 帧 pcap 逐字节、`ΔW56 = 0`）证明图案流没有被打洞。
- **但"`ΔW45 = +2274 = ΔW29`"这半句作为"印证"是空的**：它只是同一条谓词被读了两次（顺带说，它**唯一**能见证的是"wrapper 的 `tx_fifo_full` 与 FIFO 内部 `full_r` 确实是同一根线"这个接线事实，不是行为事实）。**下游若曾拿它当"两条独立仪器互证"，须按本条降级。**

### 1.3 ~900/s 的量级：**可以由时钟域差算出来**（这是本轮的新结论）

【事实】`board/wrapper_p4.v:293-296` 的域别名：
- **DP 域** `dp_clk` = **Y1 100 MHz × MMCM 1.5625** = 156.25 MHz（板内晶振 Y1）；
- **TX 域** `tx_fe_clk = tx_mii_clk_1` = **QPLL0 派生**（参考 = 晶振 **Y2** 156.25 MHz）—— 两块**物理无关**的晶振。

【事实】**直接量到的域差**（RATE 轮的 snap 对，窗口 2.51 s，**两个 32 位计数器都没回卷**，无 #55 回卷歧义）：

**答派单的三个子问**：

## 2. 残差 ②：两个"离群跑"

### 2.0 方法：把 11 个 LF 跑在同一批字段上逐项对账

原件 = `_proj_10g/notes/p7b_longflow_board/runs/LF{1..11}_*.txt`（每跑自带 `nic_pre/pre2/post/post2` + `ss` 采样 + 板侧 63 字快照）。本轮用脚本一次性抽取所有可比字段（脚本在 `%TEMP%`，只读）。

### 2.1 ②(a) LF5 窗内 4 个 CRC 错帧 —— **部分解释**

**先答"是不是唯一一次"**【事实】：
- LF5（`LF5_arm2b_nocheck.txt:24-30 / :220-227 / :236-243`）：`nic_pre2 → nic_post` 之间 `rx_eth_crc_err 0 → 4`（`port_rx_bad` 随后在 `post2` 也是 4 —— 两个字段更新路径不同步，见 §3）；
- **其余 10 跑的前后逐点核对：`Δrx_eth_crc_err` 全 0、`Δport_rx_bad` 全 0**；LF6–LF11 只是**继承**这个 4（累积计数）。
- ⚠️ 但"唯一一次"只对 **LF 家族**成立：同一天的 UDP 长跑里 `rx_eth_crc_err` 是 `1`（L1 前）→ `1`（L1 后）→ `2`（L2 前）→ `2`（L2 后）—— **L1 窗内新增 0，L1/L2 之间另有 1 个**。⇒ 全天板→对端流量 ~3.65×10¹² bit 里共 6 个坏 FCS 帧，其中 4 个挤在 LF5 的 ~2.2×10⁹ bit 窗内。

**LF5 独有的那一项**【事实】（同批字段对照）：

| 字段 | LF5 | 其余 10 跑 |
|---|---|---|
| `Δrx_eth_crc_err` / `Δport_rx_bad` | **+4 / +4** | 全 0 |
| `ΔTcpExtTCPOFOQueue`（对端栈乱序入队） | **+121** | 0（唯 LF7 = +18） |
| `ΔW55`（板侧整段重放次数） | 6 | 0–19（见表 §2.2） |
| `ss -m` 的 `skmem d`（对端 socket 丢包） | 46 | 0–362 |
| 速率/P/`193/P` 换算（非测量） | 7.1165 Gbps / 256.4 / 75.3% | —（coalescing 开臂，全在 6.3–8.4） |

⇒ **4 个坏 FCS 帧是 LF5 独有的 NIC 级事件**；同跑的对端 +121 OFO 与板侧 6 次重放是**它的下游后果链**（帧被 NIC 丢 → 段缺口 → 乱序/OFO → dup-ACK → 板按设计整段重放 → 恢复）。**"4 帧坏"与"6 次重放"的因果方向**：OFO 只在缺口存在时涨，4 帧 NIC 级丢弃**必然**先于 OFO ⇒ 方向为 4 帧 → OFO → 重放（【推断】，与读数自洽）。

**板侧系统性缺陷被排除的一条硬边界**【事实 + 算式】：
- L1 的 300.014 s / 809,578 fps 全链 UDP 长跑，对端 NIC `rx_eth_crc_err` **恒 1 → 1（Δ = 0）**，`port_rx_bad` 恒 1 → 1；该窗板→对端 = `Δport_rx_good_bytes = 374,375,966,736 B` = **2.995×10¹² bit**。
- LF5 的局部速率 = 4 / (183,913 帧 × 1518 B × 8) = **1.79×10⁻⁹ /bit**。若这条速率是本设计 TX 链的**稳态**属性，L1 窗里应出现 ≈ 5,360 个坏帧 —— 实测 **0**。
⇒ 【推断】这 4 帧是**突发/瞬态事件**，不是 TX 数据通路的稳态缺陷。（与 `ACCEPT.md:150-151` 的"突发/事件型"同向，本轮把边界从"远高于 P7a 的 5×10⁻¹³"加强成"同板同线 3×10¹² bit 零新增"。）
- ⚠️ 计数语境：全天 6 帧 / 3.65×10¹² bit ≈ **1.6×10⁻¹² /bit**，只有 P7a 板内环回上界（4.997×10⁻¹³）的 ~3 倍 ⇒ "总量"与"链路自身水平"同量级；**超额在"4 帧连发"这个形态上**（局部超期望 ~10³ 倍）。

**差什么（为什么只能到"部分解释"）**：
- **无 pcap**（`PCAP_ON=0`）⇒ 4 帧坏在哪里（长度/位置/是否同一突发）不可知；
- **无线路侧见证**（无 FEC/眼图/误码仪在跑）⇒ 无法在"光/连接器瞬态"与"板侧某帧几何的边缘裕量"之间裁决；
- 板侧**没有**能见证"某帧 FCS 算错"的计数器（W3/W4/W41/W42 都是**接收侧或 MAC 中止**计数，全 0；TX FCS 生成是纯组合，无自检）。

### 3.3 失效机理 = sfc 统计块的**周期刷新量化**（同仓有直测原件）

【事实】`_proj_10g/notes/p7b_rate_result/nic_quantum.sh` + `nic_quantum.txt`（V1 裁决轮为解"短窗 d_mac 落在 0.80/1.31 两个极端"而写的一次性实验）：每 0.204 s 读一次 `ethtool -S`，`port_rx_packets` 呈**阶梯**：
```
Q1..Q3 (781.68–782.09) 同值 2934738925
Q4     (782.29)        2935551916   ← +812,991（一次跳变）
Q5..Q8                 不动
Q9     (783.31)        2936364921   ← +813,005
Q10..Q15               不动
Q16    (784.75)        2937420007   ← +1,055,086（≈1.3 个"标准步"）
```
⇒ **跳变间隔 ≈1.0–1.4 s，步长 ≈813k 包（= 该测试当时的泛洪率 × ~1 s）**。
【事实】**同一次 `ethtool -S` 输出里**，`port_rx_nodesc_drops` **每个采样都在动**（114,265,227→…→116,573,540，均匀增量）⇒ 同一张表里两种刷新路径：**MAC/port 统计块是周期 DMA 快照，driver 侧计数是连续累加**。

**【推断，一行机理】** 每次 `NIC_*` 读返回的是"**最后一次刷新边界**"的值 ⇒ 该读带一个**不可见的滞后 d ∈ [0, Q]**（Q ≈ 1.0–1.4 s）；两次读的滞后**可以不同** ⇒ 计数窗 = 名义窗 + (d₁ − d₂)，误差上界 = ±Q。本读数需要 |d₁−d₂| = 0.529 s **< Q** ⇒ **落在量化误差内**。

### 3.4 三条交叉验证（都指向同一结论）

1. **同接口的"不可能读数"再现**：L1 的 `nic_pre → nic_pre2`（`log_L1.txt:30/67`，Δt = 2.507784 s）记 **Δ = 2,426,366 包 ⇒ 967,534 fps = 1.195× 几何上限** —— 与 J0 同一签名（且两窗的 Δ 只差 11 包 / 2.4M，说明两次都落在**整数个量化步**附近）。
2. **反例（排除"乘性虚高"）**：`run_STC_B2DL1.log` NIC 窗 Δpkts = **21,951**，板侧同窗 `ΔW20 = 21,951`（`0x0→0x55bf`）**逐位相等**；`B2DL2` 同样 **21,963 = 21,963**。若计数器是"乘性虚高 / 重复计数"，这两个窗也该虚高 21% —— **没有**。⇒ 计数器不是乘性错的；短流整段落在两个刷新边界之间时，读数**恰好精确**（这与阶梯模型一致）。
3. **比值口径不受影响**：`Δbytes/Δpkts = 1517.9994`（J0）与 1518.0009/1517.9999（历史读数）同族 ⇒ 整个统计块是**同一快照**被整体平移，不是某一项坏了。

**同族知识的出处（派单要求核实）**【事实】：`port_rx_*`/`port_tx_*` "与内核计数同源、非独立硬件计数"的**原始观测**在 `_proj_10g/notes/P7B_UDP_DIAG2.md:137` —— 那里是 **`port_tx_packets/port_tx_bytes` 与内核 `tx_packets/tx_bytes` 逐字相同（8223 / 1352075）**；rx 侧是**外推**（登记在 `P7B_LONGSEND_DESIGN.md:649` 与工程记忆）。⇒ 引用时口径应为"**tx 侧实证同源；rx 侧同源为登记性推断**"。

**结论：③ = 已解释**（仪器口径失效：不是板子/线路的读数；机理 = sfc port 统计块的周期刷新量化，需要的窗口错配 0.53 s 落在实测量子 ~1.0–1.4 s 之内）。
