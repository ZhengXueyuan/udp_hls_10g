## 3. ⭐ V1 裁决（计划 §3.1.3 的未决项）—— **用新增实验定案：`port_rx_*` 是"周期刷新的快照"，不是连续计数器**

**实验**（计划里没有，本轮新增）：以 **0.204 s** 间隔连采 16 次（`nic_quantum.txt`）。

```
Q1..Q3   port_rx_packets = 2934738925  2934738925  2934738925   （连续 3 次逐字不变）
Q3->Q4   +812,991  ← 阶跃
Q4..Q8   2935551916 (不变 ×5)
Q8->Q9   +813,005  ← 阶跃
Q9..Q15  2936364921 (不变 ×6)
Q15->Q16 +1,055,086 ← 阶跃
```

⇒ **三条结论**：

1. **`port_rx_packets`（及 `port_rx_good`）是 ~1.2 s 刷新一次的快照** ⇒ 它在一个 2.5 s 窗上的增量只能取
   少数几个离散值（**量子/窗宽 ≈ 48%**）⇒ **计划 §4-N-b0 的 V1 判据（`d_mac/d_board` ∈ ±0.5%）
   在 2.5 s 窗上结构性不可达**。这就是 `d_mac/d_board` 在三轮**完全相同**的配置下给出 0.914 / 1.312 / 0.796 的原因。
2. **`rx-0.rx_packets` 是连续可读的计数器**（0.1 s 间隔稳定 +84,000/0.1 s ≈ **840 kfps**）⇒
   它**才是**可用的独立口径（§2 的 `d_dma` 就是它）。
3. 计划 §3.1.2 的"内核 `rx_packets` ≡ `port_rx_packets` 逐字相同"**仍然成立**（别名关系），
   但**推论要改**：它们**共同**是那个慢刷新快照 ⇒ **两条都不能**做短窗速率裁决。

## 4. 两条"FAIL"的定案（⛔ **标题原文"口径错，不是板子"已于 2026-09-30 晚作废**）

> ⛔ **本节原判"错的是分母、不是被测量"是错的。** 本节的三条读数（`1464 / 1510 / 192.00`）
> **是同一个缺陷的三个侧面**：`rtl/app_udp_pattern.v` 的 TX 字 FIFO 写口**一拍错位的空间门**
> ⇒ **每帧静默丢 1 个整字 = 8 B**。**表里的读数一字未改（它们是真的）**，改的是**解释**：
> 下面"因此"三条里，**第 1、2 条是错的**，第 3 条（`W9` 不是线上载荷）**仍然成立**。
> 定案链：`P7B_W9_GAP.md`（定案）→ `P7B_W9_GAP_VERIFY.md`（**对抗复核，推不翻**，并用
> `mac_tx_10g` 帧周期 `(192.000, 19.000)` 在 1500–1520 内做成 **C=1506 的独占签名**）
> → `P7B_BIZ_S2.md` §2.3（修复后的逐条期望：**1514 / 1500 / 1480 / 1472 / 1518 / 193.000**）。

计划 §2.2 假设：载荷 1472 B / 线长 1518 B / 193.24 拍/帧（⇒ 期望帧率 808,579）。
实测三个仪器给出同一套几何（下表的读数**全部有效**）：

| 仪器 | 读数 | 推出 |
|---|---|---|
| **① pcap 逐帧**（`frame_len.txt`，40/40 帧**长度集合 = {1506}**，`-s 0` 无截断） | `ip_tot = 1492` · `udp_len = 1472` · **载荷 = 1464** · `eth_len = 1506` | 线长（含 FCS）= 1506+4 = **1510** |
| **② 对端 NIC 字节计数** | `Δport_rx_good_bytes/Δport_rx_good =` **1510.0000**（四轮逐字相同） | **1510** |
| **③ 板侧 `W43/W20`** | **192.000**（四轮逐字相同） | 1(前导)+**189**(内容)+**2(IFG 字)** = **192** |

⚠️ **订正一处算术**（原标题行原写 `1(前导)+190(内容)+2(IFG 字) = 192`，**1+190+2 = 193，自相矛盾**）：
正解是 **189 个内容字**（1506 B = 188.75 字 ⇒ 占 189 字）；**190 是 1518 口径的数**，
写在这里容易被后人反推出错的口径（`P7B_W9_GAP_VERIFY.md` §2.4 已独立指出并逐字证实：
C=1506 → (192, 19)，C=1514 → (193, 19)）。

**自洽性核验（全部逐字成立）**：
```
ETH 14 + IP total 1492 = 1506 (pcap) ;  +FCS 4 = 1510 (NIC)
IP total 1492 = 20(IP 头) + 1472(UDP 数据报)
UDP 1472 = 8(UDP 头) + 1464(载荷)
1506 B 帧 = 188.75 字 ⇒ 占 189 字 ; +1 前导字 = 190 ; +2 IFG 字 = 192 ✓
IFG = 2 字 = 16 B ≥ 802.3 下限 12 B ✓ （MAC 的 ETH_IFG_IDLE=12 决定了这个 2 字）
```
⇒ 自洽性**照旧成立**（它是"缺陷态几何"内部自洽）—— ⚠️ **但"自洽"不等于"正确"**：
同一套算式在修复后的几何上给出 `1506→1514`、`189→190`、`192→193`，**两套都自洽**。

**因此（⛔ 第 1、2 条已订正）**：
- ⛔ ~~`A1` = 192.000 是**本构建的设计真值**~~ ⇒ **改**：192.000 是**缺陷态读数**（每帧少 1 字）；

## 7. 本轮新增的三条方法学结论（供后续引用）

1. **`port_rx_*` 是 ~1.2 s 刷新的快照**（§3）⇒ 短窗速率裁决**必须**用 `rx-0.rx_packets`（连续计数器）
   或把窗口拉到 ≥20 s。**"MAC 计数与板侧 ±0.5% 对账"这条判据形态本身要改**（不是把容差放宽了事）。
2. **锁存后先读 NIC、再 dump 51 字**：快照是**锁存**的，读回耗时（本机实测 **dump A = 0.104~0.115 s**）不改变锁存时刻，
   所以可以把 NIC 采样压到锁存外 **5~14 ms**（宽度偏置仅 +0.06%~0.59%）。这是本轮"四项差分账"可信的前提。
3. **40 字节的 pcap 就足以钉死速率口径**（帧长集合 + IP/UDP 长度字段），代价 ~1 s，
   **不必**依赖任何"逐字节图案校验器"（后者在 800 kfps 下结构性不可用）。
