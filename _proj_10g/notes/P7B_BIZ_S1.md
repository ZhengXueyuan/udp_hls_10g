## 5. ⭐ 本轮新发现（给下一轮；两条都是"设计/台架"级）

### 5.1 板子在 TCP 下行**每条连接多发 ~11.9 个"重复 seq"整段**（未定位）

| 观测 | 读数 |
|---|---|
| pcap 全量统计 | `data = 219,272` 帧；**`dupseq = 3,572`**；`uniq` 每连接 **恰好 719 段 = 1,048,576 B** |
| 与板内计数对账 | `ΔW15 = 319,787,920 B`；对端收到 `314,572,800 B`；**差 = 5,215,120 = 3,572 × 1460 精确** ⇒ 两条口径**在扣除重传后逐字节相等** |
| `ΔW14` 对账 | `219,573 帧 = 300×(719 数据 + 1 FIN) + 3,573` ⇒ 同样的 3,572 段 + 1 |
| **真的在线上吗** | ✅ **在**：单连接实验对端 NIC 计 **749** 帧 vs pcap **745** 帧（含 27 dup）⇒ **不是抓包幻影** |
| 位置特征 | 全部落在**每连接流的前 ~2 个十分位**（偏移 0…208,780 B）；`dup` 时间在连接开始后 **0.105 → 4.16 ms**（连接总长 ~9.28 ms）⇒ **集中在连接前段、按 seq 顺序成块重传** |
| 后果 | 逐字节流**不受影响**（TCP 去重；`gaps = 0`、`first_mismatch = -1`）。代价 = **1.658% 的额外线上载荷** |
| 为何本轮**无法**定位 | `tx_stat_retx` **不在 51 字窗口**（方案 R4 / F5b）⇒ 必须 Stage 2 加字（方案 §7-e） |

⚠️ **这条否证了方案 J3 的隐含假设**：J3 写"`ΔW15/(ΔW24/156.25e6)` 与对端 socket 收字节/墙钟差 ≤ 0.5%"。
只要重传存在，这个差**必然**是 ~1.7%。**判据要改成"扣除重传载荷后 ≤0.5%"**（或直接用对端口径裁决）。

### 5.2 **2 次非受令的 carrier flap**（未定位）

`carrier_changes` 序列：**7**（18:53, S0.7）→ **9**（19:00, S1.5 前）→ 10（TX_DIS）→ 11（恢复）。
即 **18:53–19:00 之间发生了 2 次链路 flap**，而这段时间正是 S1.0/S1.1/S1.2/S1.3/S1.4 的板级测试。
同时 `rx_eth_crc_err` 3→4 也落在这段。**但**：全程 `ΔW3 = 0`（板侧 FCS）、字节流零错、零丢、零重传以外的异常。
⇒ **未定位**（可能是 GT/PCS 重同步；也可能是 SFP 模块在 9.5 Gbps 起流时的瞬态）。
**下一轮应加一条"`carrier_changes` / `pcs_evt_bundle` 逐段采样"**（方案 §5-U4 现有判据抓不到它）。
