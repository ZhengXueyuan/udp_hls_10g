## ① 新机制：装载拍 wrap-safe 钳位（v2 核心新元素）

**形状逐字核**（`rtl/tcp_tx_frame.v` 现核；落点 = `if (svc_x)` 锁存块内，锚 `:1131-1135` 成立）：

```
:1131  retx_hi <= (fin_sent_r[svc_id] && svc_rewind) ? fin_seq_r[svc_id] : rb_snd_nxt;
v2 补: ring_hi <= ((rb_snd_nxt - whi_r[svc_id]) < 32'h8000_0000) ?
                  whi_r[svc_id] : rb_snd_nxt;
```
- 阈值 `2^31` / 方向 `<` ⇒ 接受条件 = "`whi` 在回绕意义下 ≤ `snd_nxt`" ✔；退回值 `rb_snd_nxt` ✔（非 FIN 支 = `retx_hi` ⇒ `ring_delta = 0` ⇒ 不重放）。

**(1) "为什么不用 wrap-safe max" 的理由 —— 成立（附两条修正）**【事实+推断】：
- 方向论证对：max 保"**不被压低**"（单调），而 E3-6 危险是"**陈旧偏高**" ⇒ max 让大值活下来、结构上关不掉 ✔。钳位确实更强。
- ⚠️ **修正 A（归因不精确）**：钳位**新增**的覆盖只有"`(snd_nxt − whi) ≥ 2^31`"那一半。另一半（陈旧 `whi` 在回绕意义下**落后** `snd_nxt`）**本来就被既有 `ring_ovf` 挡住**：接受 ⇒ `ring_hi = whi`（落后）⇒ `ring_delta = whi − snd_nxt` 巨大 ⇒ `ring_ovf = ((snd_nxt − whi) < 2^31) = 1` ⇒ `ring_start/replay_jump/ring_restore` 全 0（`:767/:772` 与 v2 的 `ring_restore` 条件）。⇒ "钳位双向都管"应改写为"**钳位杀 ≥2^31 支；落后的陈旧支由既有 `ring_ovf` 兜**"。
- ⚠️ **修正 B（"被压低"方向没人管）**：若 `whi` 被**错误压低**，钳位会**接受**低值 ⇒ `ring_ovf=1` ⇒ **静默不重放**（真数据不重传）。现盘唯一降 `whi` 的写者是 `cfg_up` 清位（语义正确：新连接无数据）⇒ 不可达；但 §3.2-(4) 把"snd_nxt 写者清单"前置降级为"复核项"时**没有为 `whi` 的写者集合立同款纪律** ⇒ 建议补一句："`whi` 的写者集合必须保持 = {活帧推进写, `cfg_up` 清位}；任何降 `whi` 的写者 ⇒ 静默不重放"。

**(2) 它真的关闭 U3 吗？ —— 成立（对"伪重放"这一害），但它把同一情形换成了另一个角**【事实+推断】：
- `whi=0 ∧ snd_nxt ≥ 2^31`：钳位判假 ⇒ 退回 `rb_snd_nxt` ⇒ `ring_delta=0` ⇒ 不重放 ✔（v1 的"看似正的大数 ⇒ 伪重放"确实被关）。
- ⭐ **但**（我新核出的角）：该情形若同时落在 **FIN 支**（`fin_sent_r && svc_rewind`），退回值 = `rb_snd_nxt`，而 `retx_hi = fin_seq`。**`snd_nxt = fin_seq + 1` 是 FIN 支的常态**（+1 预留后不再写数据）⇒ 退回支给出 `ring_hi = fin_seq+1 > fin_seq = retx_hi` ⇒ **A4（`ring_hi ≤ retx_hi`）违反**。
  - **合法可达性**【推断】：需要 `whi = 0`（连接零数据 —— 合法：app 只 close 不 send）+ FIN 已发未确认（`snd_nxt ≠ snd_una` ⇒ `svc_rewind=1`）+ `snd_nxt ≥ 2^31`（**ISN 随机 ⇒ 板上 ~50% 量级**）。TB 臂**不可达**（ISN 硬编码全 `< 2^31`，`tb:280-281`）。
  - **无功能实害**（我逐项核过）：`ring_delta = 0` ⇒ 不重放；`ring_restore` 的 `(retx_hi − rb_snd_nxt) < 2^31` 门把它挡住（`fin_seq − (fin_seq+1) = 0xFFFFFFFF ≥ 2^31` ⇒ 不触发）⇒ 只会让 **`e_ringhi` 红**（见 §2）。
- ⇒ §3.2-(5) 的"**结构性成立**"应收窄为"**接受支 + 非 FIN 结构性成立；退回支 FIN 角可违反（无实害）**"；U3 口径应写"无害化（伪重放没了），但落到 A4 退回支"。

**(3) 它会不会误钳合法大跨距会话？ —— 不成立（不可达）**【推断】：
- `whi` 每个**活帧**推进写都跟住 `snd_nxt`（同源同拍：`f_seq+f_plen` 与 TCB 写同拍，`:1069-1077` 区 v2 落点）；会话期 `whi` 冻结（我复核了 v2 的**六支穷举**：`start_data`（`:666-669`）的合取项逐支必假 —— 穷举**完备** ✔，且 `:524 rx_idle = (rx_state==RX_IDLE) && recv_first` ✔）。
- ⇒ `snd_nxt − whi` = 控制帧 +1 累计（漂移），量级 = 笔数；2^31 笔不可达 ⇒ 无合法大跨距。**唯一**能造出 ≥2^31 的都是重基/陈旧值 ⇒ 钳掉是对的。
- 万一误钳的后果 = 静默不重放（危险方向）⇒ 与修正 B 合并登记。

**(4) 落位 / A1 同款风险 —— 不成立**：
- 钳位在 `ring_hi` 锁存（`if (svc_x)` 块内，锚 `:1131-1135`），索引 = `svc_id`（`= svc_id_r`，`:560`）—— **与同块既有的 `retx_hi` / `fin_sent_r[svc_id]` 同拍同索引** ⇒ 不新增索引风险，**不踩 A1 同款** ✔（A1 是"写口兜底 `svc_id` 与 `retx_id_r` 不等"的问题，管的是 `upd_id`）。
- TCB 写口上：`upd_sel` 是本模块**硬编码 `3'd1`**（只写 `snd_nxt`，`:634`）⇒ 无选择问题 ✔；`upd_id` 的 v2 补丁 `((replay_jump || ring_restore) ? retx_id_r : svc_id)` **必要且正确** ✔（我复核：`ring_restore` 拍上 `upd_wr_data/upd_wr_ctrl/replay_jump` 三支结构性全 0，兜底确会落到自由重算的 `svc_id_r`，`:1078`）。

## ③ 判据口径重写（D2/D3/D6）

**1) "可治的 3 条"可判定吗 —— 成立（但绑定字面、不稳健）**【事实】：

**2) ⭐ 遗漏的耦合（本报告第二个关键）—— §5.2/§5.5 的"清 0"预测不完整**【事实+推断】：

- 【事实】pre-fix 下正是**幽灵帧**把前沿推过漂移区（`[S#3]` 帧 `fseq == exp_new = 246436` ⇒ 命中 in-order 支 ⇒ `exp_new ← 246457`）；这也是 pre-fix `J9 = 0` 的成因（`orS_oracle_v6_xs.log:2710` 逐字 `… F1_ring=0 J9=0`）。
