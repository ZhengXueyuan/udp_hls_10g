A. 帧几何 (由发帧 FSM 逐拍复现, 不是读注释)
==============================================================================
pkt_len (FIXED_PACKET_LENGTH) = 256   xfer_cnt = 32 个 XGMII 字
FSM 实际发出 256 字节 = 32 字 x 8
  word0     = /S/ + 6x55 + D5 (前导/SFD, c[0]=1)  = FB 55 55 55 55 55 55 D5
  word1     = DA + SA[47:32]                       = FF FF FF FF FF FF 14 FE
  word2     = SA[31:0] + type + payload[0:1]       = B5 DD 9A 82 06 00 00 00
  word3..30 = payload  (d_sel hardwired 0 -> 全 0)
  word31    = payload[0:3] (+ FCS 由 end_packet 顶掉 lane4..7; 本函数不含 FCS) = 00 00 00 00 00 00 00 00

上线的"帧"(网卡按 DA 起算, 含 FCS)      = 248 字节
  ↳ 与闸 2 的网卡硬件计数 Δbytes/Δpackets = 248.000000 **逐字节吻合**
其中被 FCS 保护的部分 M244              = 244 字节  (14 头 + 230 载荷)
厂商 RTL 实算的覆盖长度 CRC_N           = 252 字节
  ↳ 差值 = 8 字节 = word0 那个"前导+/S/"字
  ↳ 头 14 B 两边一致; 多算的 8 B 全是 d_sel=0 的常量 0 比特

  ⭐ 几何的**外部确认**: P7B_GATE1.md:1085 记录了板级 XGMII 逐字 trace (该文件按
     d[63:0] 打印, 即 lane0 落在**最低**字节 = 我这三行的字节反转)。逐字比对:
      板级 word0 = 64'hD5555555555555FB   vs 模型 bswap = 0xD5555555555555FB  True
      板级 word1 = 64'hFE14FFFFFFFFFFFF   vs 模型 bswap = 0xFE14FFFFFFFFFFFF  True
      板级 word2 = 64'h00000006829ADDB5   vs 模型 bswap = 0x00000006829ADDB5  True
      板级 "29 个全 0 字" (word3..word31)  vs 模型 = 29 个字, 全 0 ? True

==============================================================================
B. 逐位复现 gen_CRC_const 并与 zlib.crc32 对拍
==============================================================================
  zlib.crc32(M244)              = 0xD5D89E7F   (标准 CRC-32 值)
  zlib.crc32(M244||0x00*8)      = 0x10DD3F5F
  RTL gen_CRC_const(244, 0)     = 0x7F9ED8D5
  RTL gen_CRC_const(252, 0)     = 0x5F3FDD10   (厂商参数 pkt_len-4)
  ⚠️ 两边的 **32 位整数**差一个字节序约定 (RTL 的 op_crc = 标准值的字节反转),
     所以对拍必须落在**上线的 4 个字节**上, 不能比整数 —— 见下。

  RTL(244) 上线序 (word31 lane4..7) = 7F 9E D8 D5
  RTL(252) 上线序 (word31 lane4..7) = 5F 3F DD 10   <-- 厂商实际发出去的
  zlib(M244) 的 little-endian 4 字节 = 7F 9E D8 D5
  zlib(M244) 的 big-endian 4 字节    = D5 D8 9E 7F

  [判据 1] RTL(244) 上线序 == le(zlib(M244))            ? True
  [判据 2] RTL(252) 上线序 == le(zlib(M244 || 8 个 0))  ? True
  => 判据 1 把"RTL 模型"钉死在标准 CRC-32 上 (模型可信, 非自说自话);
     判据 2 说明厂商的 252 恰好 = "正确的 244 后面又追加 8 个 0 字节"。
  [判据 3] FCS 上线序 == 小端 (802.3 约定) ? True   (== 大端 ? False)

==============================================================================
C. 网卡看到了什么 (收到帧按 802.3 clause 3.2.9 校验)
==============================================================================
  正确 FCS 四字节        = 7F 9E D8 D5
  厂商插入的 FCS 四字节  = 5F 3F DD 10   (与正确值不同)
  crc32(M244 || 正确 FCS) = 0x2144DF1C
  crc32(M244 || 厂商 FCS) = 0xCFB5850F
  [判据 4] 正确 FCS 的残差 == 标准常数 0x2144DF1C ? True   (外部已知量, 独立确认)
  [判据 5] 厂商 FCS 的残差 == 0x2144DF1C (网卡判 good 的条件) ? False

  => 每一帧都会被任何 802.3 接收器判 FCS 错 (残差对不上);
     与闸 2 实测 port_rx_good=0 / rx_eth_crc_err≈100% 方向一致。
     随机帧被误判 good 的概率 ~2^-32 ⇒ 10.2e8 帧里期望 ~0.24 帧, 可忽略。

==============================================================================
D. 与闸 2 实测的逐档对账 (解释了"差分负对照没有按期望翻转")
==============================================================================
  闸 2 §5 的 C-3: crc_en=0 与 crc_en=1 两档, rx_eth_crc_err 都没有变好,
  port_rx_good 两档都是 0。本模型给出两档的**同一结论**:

  (a) insert_crc=0 (厂商 example 出厂值, `assign insert_crc = 1'b0` @ :186)
      => word31 的 lane4..7 = op_data = 00 00 00 00  (FCS 字段恒为 0)
      残差 crc32(M244 || 00 00 00 00) = 0x5ACD9360   == 0x2144DF1C ? False
  (b) insert_crc=1 (闸 2 的 v2 把它接成 VIO 可控)
      => word31 的 lane4..7 = 5F 3F DD 10  (覆盖 252 B, 见 B 节)
      残差 = 0xCFB5850F   == 0x2144DF1C ? False
  (c) 假想的"修好了"档 (覆盖 244 B)
      => word31 的 lane4..7 = 7F 9E D8 D5
      残差 = 0x2144DF1C   == 0x2144DF1C ? True

  => (a)(b) 都判坏, 只有 (c) 判好 ⇒ 与闸 2 实测的"两档都 100% 坏"完全一致。

==============================================================================
D2. 差异的另一种表述 (便于交叉核对)
==============================================================================
  厂商插入的 FCS = CRC32(M244 || 0x00 x 8)  (不是 CRC32(M244))
  即: 覆盖长度用 pkt_len-4 (252) 而不是 (pkt_len-8)-4 = 244
