## 3. 判据层的**测量学**发现（供后续引用，两条都是本轮新实测）

1. **pcap 时间戳是"批量打戳"的** —— 同一条流里 3000 条记录只有 **555 个不同时间戳**（另有 539 个），
   每个时间戳挂 2~8 条**内容不同**的帧 ⇒ **帧间隔分布不可用**（中位数会读到 0，看着像"重复副本"）。
   ⭐ **但"记录数 = 不同载荷数"（3000/3000，零重复）已自证没有副本** ⇒ **端点跨度口径仍然有效**
   （首末时间戳差 28.244 ms / 2999 帧 ⇒ 106,182 fps）。桶粒度给 **±0.18%** 的不确定度。
   ⇒ **口径 = 端点跨度 + 去重自证，禁用间隔分布**（已写进 `pcap_rate.py` / `f3_check.py` 的注释）。
2. **NIC `port_rx_*` 的 ~1 s 刷新量子**在本轮**又一次被独立抓到**：`rate_probe` 里两次 NIC 采样间隔
   **0.0918 s**，而 `Δport_rx_good = 105,901`（**= 1 秒的流量**）⇒ 折算 1.15 Mfps 的"物理不可能"读数。
   ⇒ 坐实 closeout §3.3 的结论（**窗口 < ~20 s 时它结构性反解不到 1%**），也解释了
   `N_XCHK` 的容差为何被量子项主导（9.58%）。

- 事实：`W40` 低 8 位 = `pcs_vcc_cyc`，**四块快照全是 `0xFF`**（255 → 255）；第二轮同样。
- 归因（不变）：`board/wrapper_p4.v:3366-3379` 是 **8 位饱和计数器**，`dp_clk` 156.25 MHz ⇒ **1.6 µs 饱和**；
  同段 RTL 注释自己写着"不得当精确事件数引用"。⇒ **"持续增长"在这条观测线上结构性不可判**。
- **正证据成立**：非 0（= 255）⇒ 这些状态线**确实来自核**，不是被钉 0。C8 想防的"恒 0 假干净"**没有发生**。
- **收口建议（只在报告里提，本轮不动手）**，按代价从低到高：
  1. ⭐ **不重建位流**：把判据的**形式**从"必须在涨"改成"**饱和本身就是下界证据**" ——
     该计数器在 1.6 µs 内数到 ≥255 个 `valid_ctrl_code` ⇒ 任何 ≥1.6 µs 的窗口都有
     **≥255 个/窗口** 的硬下界（配合 C2/C3 的 `block_lock`/`rx_status`），比"读两次比大小"更有判别力；
  2. **重建位流**（观测面改动）：`pcs_vcc_cyc` 加宽到 ≥16 位，或另加 1 位 tick ⇒ 恢复"在涨"语义。

## 6. 本轮新增的两块证据

### 6.1 F3 的**新方法**（不需要重烧，逐帧更全）

**动机（本轮实测的硬约束）**：板子在 106k fps × 1472 B ≈ **156 MB/s** 推进图案流 ⇒ 跑几分钟偏移就到
**GB 级**，任何"从 offset 0 顺序搜索"的校验器**结构上不可能**命中（第二轮的 `content_check3.py`
搜索窗只有 6000 帧 = 8.8 MB，**只能靠重烧复位**）。

**新方法**：xorshift64 的三步（`^<<13` / `^>>7` / `^<<17`）**全是 GF(2) 上的线性映射**，
输出 `s[31:24]` 也是线性的 ⇒ **8 个连续输出字节（64 bit）就已超定地定出初始状态**。
工具 = `xs_lib.py`（求解器）+ `xs_solve.py` / `f3_check.py`，**判据自带自检**（3 正：随机状态必须解回；
3 负：随机字节必须被判矛盾）—— 自检不过就**不出结论**。

**读数**（`g4_f3.pcap` = 13:48 抓的 3000 帧全载荷）：

```
J0 求解器自检: 3 正 OK / 3 负 OK
J1 首帧反解: 状态 = 0x48DA2B153E550B4B (自由位 0)
J2 逐帧逐字节 == 复算流 的帧 = 3000 ; 不符 = 0
J3 相邻帧载荷长度分布 = {1472: 2999} ⇒ 步长恒 1 帧 (= 1472 B) = True
   覆盖 = 3000 帧 × 1472 B = 4,416,000 B ; 无空洞 = True
J4 时间戳 Δ=0.028246 s ⇒ 106,174 fps ; 不同载荷 = 3000/3000 (重复副本 = 0)
⇒ J1∧J2∧J3 = PASS
```

**与第二轮方法的差别（如实标注）**：第二轮用"重烧 ⇒ 偏移 0 锚定"（好处：证明抓包没漏首帧）；
本轮不重烧 ⇒ 首帧偏移是**反解出来的**（不是 0），但**逐帧覆盖率更高（3000/3000）**
且**步长恒 1 帧**这一条**独立地**证明了抓包内部无空洞/无重复。
⇒ **两轮结论一致（字节级清白），本轮方法更强、代价更低**；"重烧后第一帧 == 偏移 0"这条
**本轮未复验**（它是抓包完整性属性，不是数据正确性属性）。

### 6.2 F5（TCP fast path @10G）—— 从"未测"到**定性 PASS + 两处缺口**

**工具**：`f5_probe.sh`（板侧前/后快照）+ `tcp_echo_probe.py` / `tcp_dump.py`（对端侧激励）+ `f5b_rx_probe.py`（正/负对照）。

| 事实 | 读数 |
|---|---|
| TCP 握手 @10G | **5/5 全部成功**（`connect` 0.10–0.20 ms）—— 板侧 = HLS 慢路径 (`hls/src/layer_tcp.cpp:17` `TCP_PORT_ECHO 8080`) |
| TCP **TX**（fast path 发） | 从**全 0** 起：`W14`(TCP 发帧) 0 → **1592**（f5_probe +76、f5b +1458）；`W15`(TCP 发字节) 0 → **2,290,952 B**（+96,488 / +2,114,672；≈1450 B/段） |
| ⭐ TCP TX 流的**内容** | 收到的字节**不是**我的回显期望（我一开始就期望错了：板子**不回显**，它**发自己的图案流**）。用 GF(2) 求解反解首 96 B ⇒ **状态 == `0x9E3779B97F4A7C15`（公共种子·偏移 0）** ⇒ 收到的是**图案流且每连接归零**，与 `P5d` 文档的语义逐字一致 ⇒ **"回显不匹配"是我的期望错，不是缺陷** |
| TCP **RX**（板侧收） | `W22`(fast path 接受帧) 0 → **1493**（f5_probe +48、f5b +1411；含对端 ACK）；`W23`(nonmatch) 0 → **7**；`W0`(RX 帧) 同窗 +1421 |
| 通道健康 | `W3`(FCS 错) **整场 = 0**；`W39` **= 0x2000100C 不变**（block_lock/rx_status=1、no fault）；`gen` 每次恰好 +1 |
| app 侧 TCP 载荷校验 | `W10/W11/W13` **全程不变**（`1/100/0`）⇒ **本构建的 app 是 UDP 图案 app（`udpapp_*`），TCP 载荷没有消费者** ⇒ `f5b_rx_probe.py` 的 J_f5a/J_f5b（让 app 校验 TCP 载荷）**口径不适用**，**不能**据此说 TCP RX 载荷对或错 |
| 重传/RTO 计数 | ❌ **结构性不可读**：`tx_stat_retx` 是 wrapper 的**内部 wire**（`board/wrapper_p4.v:1496`），**不在 51 字快照窗口内** ⇒ F5 判据里"重传计数不异常"这一半**本轮无法评估** |

**F5 结论（分三段写，不许合并）**：
1. **定性 PASS**：握手成立 + TCP 双向都在搬数据（`W14/W15/W22/W0` 都涨）+ 通道不掉链（`W3`=0、
   `W39` 位段不变、无 carrier flap）+ **TX 方向载荷逐字节等于图案流**（独立复算，见上表）。
2. **未测 ①**：**RX 方向载荷逐字节**（本构建 app 不消费 TCP 载荷；UDP teach 未复跑）。
3. **未测 ②**：**RTO/重传计数**（观测面没有这个字；要闭合需**改观测面**，不是本轮能做的）。

## 11. 结论

1. **fix3 的三条修法在真板上全部按设计工作**（`T_RUN` 拆分的硬判据、`N_SELF` 的 ±1 容差、
   `N_XCHK` 守卫修复 + 同刻编排）⇒ 验收脚本从 `PASS=23/FAIL=3` 变成 **`PASS=26/FAIL=1/SKIP=1`**。
   ⚠️ **其中 2 条是"判据改了"（`T_RUN`/`N_SELF`），1 条是"判据修好了、首次真的评估"（`N_XCHK`），
   没有一条是"现象变好了"** —— `C8` 更是原样 FAIL。
2. **唯一 FAIL = `C8`**：8 位饱和计数器上"在涨"不可判；**正证据（非 0）成立**，判据一字未改，
   便宜收口建议见 §4。
3. **F3/F4 都换成了不依赖该失效工具的独立口径**：F3 = 3000/3000 逐字节 + 步长恒 1 帧
