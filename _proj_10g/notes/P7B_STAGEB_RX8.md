全部包在**既有宏 `P7B_10G`** 内（该宏只有 P7b 的 10G 构建/门在定义），未定义时预处理器原样吐回原语句。

**语义要点（逐条都对得上既有合同）**：

- `rx_tready = (rxs == 2'd0)` **一字未动** —— 宽路径靠"不进比较态"做到 1 拍/字，
  **没有放宽背压合同**（对比 UDP 版必须放宽 `rx_tready` 并修 `nx_v <= rx_ld` 那个坑）。
- 计数口径与串行路径**逐字节同款**：`stat_rx_bytes` / `stat_mismatch` 都是"每字节"（不是每拍）。
- 尾字（`pop8≠8`）与 0 长字**结构性回落**既有路径 ⇒ 非 8 倍数载荷正确，**没有第二套尾字实现**。
- `rw_*` 照旧锁存（回落路径入口拍总会重锁，因此宽拍不锁存也不影响正确性）。
- ⚠️ **`!ev_up`（本轮新增的 hardening）**：`ev_up`（每连接复位）与"本拍有字"撞车时，宽路径**让位**。
  理由：串行路径在该拍**不写** `rx_lfsr`（只写 `rxs<=1`）⇒ 复位照常生效；而宽路径会写
  `rx_lfsr <= rx_lfsr_8` 把复位**盖掉** ⇒ 两条路径在那个角落分叉。让位后两边逐位同行为，
  代价 = **每个连接起点慢 1 个字**（那一拍退回串行比 8 字节）。
  ⛔ **2026-10-07 就地订正 + 登记（P7B_STAGEB_FIX.md；审查 B2 第②条 = `P7B_STAGEB_RX8_REVIEW.md` §1.1）**：
  上面"串行路径在该拍**不写** `rx_lfsr`（只写 `rxs<=1`）"这句**只对【握手拍】成立**：
  - 握手拍走 `:732-733` 的 `else rxs <= 1` ⇒ 确实不写 `rx_lfsr` ⇒ **让位硬化在该拍有效**（变异 F 有牙，读数见 §3）；
  - **比较窗内**（`rxs==1` 的拍，例如 `ev_up` 在与字流握手后第 4 拍落下）走 `:736` 的 else 分支 ⇒
    `:739` 的 `rx_lfsr <= xs_next(rx_lfsr)` **无条件写** ⇒ **同拍后写覆盖 `:530-532` 的 `ev_up` 复位**
    （`:531` 的 `rx_lfsr <= SEED`）⇒ 该相位下 **A/B 分叉**：
    **最小反例** = A（默认）`rxb=44 mm=28` vs B（`P7B_10G`）`rxb=48 mm=32`，
    机理由 TB 运行期证据钉死（`EVID mid ev_cycle: tready_mid=0`（默认构建那拍 `rx_tready=0` ⇒ `rxs==1` ⇒
    撞在比较窗里）vs `tready_mid=1`（`P7B_10G` 那拍空闲））；逐数对账见审查 §1.1 的两列表。
  ⇒ **口径收窄为"除该相位窗外逐字节等价；窗外 B 更符合文档意图"**（B **应用**每连接复位 = 文档意图；
    A **静默丢弃**复位 = 既有 quirk）。**不能靠加固修掉**：B 里根本不存在"满字的比较窗"这个状态，
    无法复现 A 的丢弃行为（彻底同行为 = 让默认路径也别丢复位 = 改默认构建，另立项）。
  ⚠️ 该窗真实可达（DEL→ADD 背靠背/同槽重连时 `o_ev_up` 单拍脉冲与 RX 字流无对齐关系）；影响面 =
    `stat_rx_bytes`/`stat_mismatch` = 快照 **W53/W54** 的读数可分叉（**非功能影响**）。
  出处：`P7B_STAGEB_RX8_REVIEW.md` §1.1（反例门 `sim/p7b_stageb_rx8_review/run_evphase.bat`，三次重跑逐字相同）。

## 2. 算式（**按设计审查的四条订正后的口径**）

```
结构上限        = 8 B/拍 × 156.25 MHz = 1,250 MB/s = 10.000 Gbps      （= XGMII fabric 侧带宽）
1460 B 段       = 182 满字(1456 B) + 1 个 4 B 尾字 = 183 字
R1 拍数(实测)   = 182×1 + (1 取值 + 4 比对) = 187 拍 / 段
              ⇒ 1460/187 = 7.8074866 B/拍 × 156.25 MHz = 1,219.9 MB/s = 9.759 Gbps（结构值）
默认路径(实测)  = 182×9 + 5 = 1643 拍 / 段 ⇒ 0.888679 B/拍 = 1.1109 Gbps（= 板级 1,110.8 Mbps 的出处）
```

**审查订正的四条（引用时必须照这些数，不许沿用设计件旧说法）**：

1. **链上真正的限速级是 `tcp_rx` 的 190 拍（7.6842 B/拍），不是 app**。
   对线上预算的余量 = **`+1.18%`（192.25 拍口径）/ `+1.58%`（193 拍实测口径）**；
   app 侧 187 拍只是 **97.27%**（tcp_rx 98.83%）。⇒ **"8 路够不够"由 `tcp_rx` 决定**。
2. **可达天花板写 `9.456 Gbps`**（`1460/193 × 156.25 MHz`，193 = 实测帧周期）；
   `9.493 Gbps`（`1538/8 = 192.25` 拍）只是**理论**值，两个数都要标口径。
3. **校验器拍数上界 = `⌊L/8⌋ + [r≠0](1+r) ≤ L/8 + 8`**。⚠️ 设计件的 `≤ L/8 + 2` 是**真错**
   （`L=1460` ⇒ `187 > 184.5`，用它自己的例子即可证伪）。与线上预算比：
   `⌊L/8⌋+1+r < (L+78)/8 ⟺ (7/8)r < 8.75 ⟺ r < 10` ⇒ **恒成立（r≤7）** ⇒ 结论（app 永不是限速级）不变。
4. ⚠️ **"不同族 ⇒ 风险低"是伪因果**：支配 DP 域余量的实际量是 **P&R 重排 ±0.4~1.3 ns**，
   而 **Stage A 后 DP 域余量只有 `+0.100 ns`**。本刀**没有构建读数**（§5）。

### 3.1 逐字节等价（照 `P7B_RATE_8WAY.md` 的"五重"形态，本刀的落点）

> ⛔ **2026-10-07 就地收窄（P7B_STAGEB_FIX.md；审查 #1）**：本节的"逐字节等价"**有界** ——
> 只覆盖 `ev_up` 落在**握手拍**的相位；`ev_up` 落在**比较窗内**时两构建分叉（见 §0-3 与 §1 的订正块、
> §5-6 的登记）。⇒ 口径 = "**除该相位窗外逐字节等价；窗外 B 更符合文档意图**"。
> 本节五重证据本身（8 文件逐字节 / 边界 / 注入 / 独立复算 / 负对照）**全部仍然成立**。

1. **逐字节比对（核心）**：同一 TB 两种宏各跑一次，**8 个文件 `fc /b` 逐字节相同**。
   其中 5 个是 RX 侧**被接受的字流**（`tdata/tkeep`，按握手拍记录）⇒ 证明宽路径**没有丢字/重字/乱序**
   （队列只在真握手拍推进）；1 个是 TX 载荷字节流 + 1 个每帧字节数 ⇒ 证明 **TX 一字未变**。
2. **边界**：段长 **0 / 1 / 5 / 8 / 9 / 1460 / 1472 / 2000** 全部在同一条 989 字/7875 B 的队列里，
   两种节奏（有间隙 / 零间隙）各跑一遍 ⇒ `rxb=7875 mm=0` 两臂相同。
   （2000 B 是"超长尺度"；真链路里 >1500 B 段被 `tcp_rx` 丢弃，此处是单元级压力项。）
3. **注入（判别力）**：满字 lane1 / lane7 各翻 1 位必须**恰计 1**；同一字两 lane 翻位记 **2**；
   尾字**无效 lane**（超出 `pop8(tkeep)`）翻位**必须不抓**；尾字**有效 lane** 翻位记 1；
   0 长字记 **0** 字节 0 失配；整字取反记 **8**。实测逐数吻合（I0 48/4、I1 26/11）。
4. **独立复算（不信 DUT 自报）**：`check_rx8.py` 用**纯 Python 订单模型**（SEED + xorshift64 递推）
   重放每个实例的**接受字流**，独立算出 bytes/mismatch，与 DUT 自报**逐数相等**；
   并与 `peer.exe --pat-selftest` 的 oracle 三方互证（前 16 字节 `7F 0B 02 E5 …`）。
   TX dump 的 12000 字节 == 模型序列前缀；每帧字节数 == `[1460]×9`。
5. **负对照（必须变红，真跑）**：C/D/E/F 四个变异件由 `make_negctl_rx8.py` **每次从当前 RTL 派生**
   （不会陈旧），逐一变红且**红的判据各不相同**；F 的判别力收紧到"恰好 1 条红且是 EV 判据"。
