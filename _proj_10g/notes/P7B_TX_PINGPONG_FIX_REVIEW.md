## F1（最重）"下一个帧首拍最早 T0+2 / 余量 ≥1 拍" —— **假**

**定稿原文**（§1.3-①）："上一帧的推进写在交接拍 T0（`RX_FIN` 末拍），TCB 寄存器在 T0+1 落地，而 `bank_rdy` 被清要等 TX 引擎的 `T_DONE`，且该清除最晚 1 拍后可见 ⇒ **下一个帧首拍最早 T0+2** ⇒ 比写落地晚 ≥1 拍 ✓"

**为何假**：`bank_rdy[新 rx_bank]` 只在"该 bank 上一次被 RX 收过、而 TX 还没把它发完"时才为 1。**RX 还没领先时（冷启动 / app 空闲后恢复 / TX 追平），它是 0** ⇒ 帧首拍落在 **T0+1**。

- 证据（乒乓模板逐字）：`rtl/udp_tx_frame.v:281-286`（RX_FIN 末拍：`bank_rdy[rx_bank]<=1`、`rx_bank<=~rx_bank`、`rx_state<=RX_IDLE`、`recv_first<=1`）+ `:201`（接受门 `(rx_state==RX_IDLE) && !fifo_full && !bank_rdy[rx_bank]`）⇒ **T0+1 拍 `rx_idle=1` 恒成立**；`bank_rdy[~rx_bank]` 的取值由 TX 进度决定，不由 RX 决定。
- TCB 侧：`rtl/tcb.v:91`（`snd_nxt_r[upd_id] <= upd_val`，同步写）+ `:110`（`rb_snd_nxt = snd_nxt_r[rb_id]` 组合读）⇒ 写落地 = T0 沿，可见 = T0+1 ⇒ 帧首拍在 T0+1 时**读到的是新值**（仍然对），但**余量是 0 拍，不是 ≥1 拍**。

### 最小反例 E1（激励 / 期望 / 实际）

```
激励：bank_rdy=2'b00（冷启动或 app 空闲后恢复），app 背靠背推两帧 A、B。
      A 的最末字在 T_last 被接受（tlast）⇒ T0 := T_last+3 为 RX_FIN 末拍（fin_cnt==2）。
期望（定稿 §1.3-①）：B 的帧首拍 ≥ T0+2。
实际：T0 沿 —— bank_rdy[X]<=1 / rx_bank<=~X / recv_first<=1；
      T0+1 拍 —— rx_idle=1、bank_rdy[~X]=0（TX 此刻才刚 T_HDR 发 A，还没碰 ~X）
                ⇒ B 的帧首拍**就在 T0+1**，`f_seq[bank] <= rb_snd_nxt` 取到 T0 拍写下的值。
      ⇒ 余量 0 拍。
```

**为什么这条必须挡**（不是文字洁癖）—— 定稿 **§7.2 时序退路梯 ①**：

> "① 给 `upd_wr/upd_val/upd_id` **加 1 拍寄存器**（固定延后 1 拍，保持写序，不改变任何不变式 —— 因为"写必须早于下一个帧首拍"有 **≥1 拍余量**，见 §1.3-①）"

- 加了 1 拍寄存器后：T0 拍的写值 **T0+1 沿**才落，**T0+2** 才可见；而 E1 的帧首拍在 T0+1 ⇒ 读到的是**陈旧基址**（= 上一帧的基址）⇒ `w_tap_seq` 从上一帧基址重写（§3-C1 的 ring 覆盖）+ 帧头 seq 复用（§3-C2/C5 的同 seq 两段）。
- ⇒ **退路① 把定稿自己列的头号反例原样搬回来**。这不是"没余量"，是"余量 0 却按 ≥1 拍写退路"。
- 同时它污染的另一处：`ring_delta = retx_hi - rb_snd_nxt`（`:317`）若在重放会话启动前多等 1 拍，会话终止判据的拍账（§3-C4 的"晚 ≥2 拍"）也要重算。

**修法（不改主设计，只改纸）**：① 把 §1.3-① 的最早帧首拍改成 **T0+1（余量 0）**，并说明"正确性来自'写落地 ≤ 帧首拍同沿可见'，不来自任何拍余量"；② **删掉退路①**，或改成"同时把该帧的 `start_data` 也推迟 1 拍"（那就等于没退路）；③ Gate A 增一条覆盖见证：**"data 帧的 RX_FIN 末拍 → 下一 data 帧首拍 = 1 拍" 命中 ≥ N 次**（现有见证集没有这一格，见 F8）。

## F2（次重）控制帧槽：三个写源互斥**不等于**槽的跨拍独占 —— 永久丢 FIN + 后续 1 字节重放（静默）

**定稿的口径**：§1.4 给控制帧**一个**槽（§5.1 "控制帧槽（第三个上下文，无 bank）"），`+1` 在该槽的 `start_ack` 拍预留。§1.2 的 `start_ack` 门 = `rx_idle && ack_pend_r && !ackq_empty && !flush_pend`（"其余条件逐字保留"）——**没有"槽空"这一项**。§2.2 则宣示"三源收拢到互斥拍 ⇒ TCB 单写口无争用"。

**缺口**：`start_ack` 每拍都能再弹一个 ackq 条目（`ackq` 深 32，`rtl/tcp_tx_frame.v:201/260/710-715`），而 ctrl 槽**从 start_ack 起就一直被 TX 引擎读到它的 `T_DONE`**（今天这条独占是靠单 FSM 隐含的：`start_ack` 要求 `state==S_IDLE`，`:334-335`）。拆引擎后这条消失：

- 第 2 个条目在 **T1+1** 拍就能再触发 `start_ack`（`rx_idle` 仍为 1 —— 控制帧的"收帧"不清 `recv_first`；UDP 模板里 `recv_first` 只被 `accept` 清 `:252-253`）⇒ 同一槽的 `seq_ctrl/ctrl_id/…` 被**覆盖**。
- 若覆盖落在 TX 引擎的 `T_HDR`（`thcnt` 0..5，逐拍读槽）**期间**，帧头字是**两个上下文拼出来**的（w0 用旧、w3 用新 ……）⇒ **线上一个 seq/ack/端口混合的垃圾帧**（对端可回 RST）。

### 最小反例 E2（最便宜的一条：一个 FIN 被丢）

```
激励：① 连接 3 的 app close（CMD=1）⇒ fin_req[3]=1（app_ctrl.v:1354）；
      ② 慢路径扫描 fin_push（tcp_tx_frame.v:659-661，条件含 rb_snd_nxt==rb_snd_una）把 FIN 条目压入 ackq；
      ③ TX 引擎此刻正在发**另一连接**的 1514 B 数据帧（占 ~191 拍，槽因此空不出来）；
      ④ 同一批到达的第 2 个控制帧（例：连接 5 的 RST，或任何 ACK 条目）在 T1+1 拍被 start_ack 弹出。
期望：两个控制帧都上线（FIN@F、RST@F5）。
实际（按定稿纸面实现）：后一个覆盖前一个 ⇒ FIN 从未上线，但它的 +1 已经写进 TCB。
```

**后果链（逐条都有行号）**：
1. `snd_nxt[3] = F+1`，`snd_una[3] = F` ⇒ `fin_push` 的 `rb_snd_nxt == rb_snd_una`（`:661`）**永久为假** ⇒ **FIN 不再有首发路径**（这是唯一的重挂入口）。
2. `fin_sent_r[3]` 恒 0（`:1133` 只在 S_DONE 置位）⇒ `fin_retx_pend[3]` 不置位（`:822` 要求 `fin_sent_r`）⇒ **RTO 重推也没有入口**。
3. 但扫描仍会给该连接装 RTO（`:942-943`：`rb_snd_wnd!=0 && rb_snd_nxt!=rb_snd_una` 为真）⇒ RTO 到期 → `svc` 回卷：`svc_rewind=1`、`retx_hi <= rb_snd_nxt = F+1`（`:820` 的 `fin_sent_r` 分支不生效）、`snd_nxt := snd_una = F` ⇒ **`ring_delta = 1`** ⇒ `ring_start`，`plen_preset = 1`（`:577-578`）⇒ **把 ring 里 `[F, F+1)` 那 1 个字节当"待重放数据"发上线**。
4. 那 1 字节是上一圈会话在 `retx_ram`（`:580-585`，13 位 ring 字下标，64 KB 回绕）里的残留内容；且 seq=F **正是对端的 `rcv_nxt`**（窗口内合法）⇒ **对端流里多出一个不属于应用数据的字节**（静默数据损坏），而 FIN 仍未上线。
5. 定稿 §1.4 的 `!ctrl_adv_inflight_for(svc_id)` 门**救不了**：那个门的依据是"槽里有一个在飞的 seq-consuming 控制帧"（`ctrl_v`），而此处槽**已经被覆盖**（`ctrl_v` 指向第 2 个帧）⇒ 门恒不触发。

**⇒ 这同时是第 6 条反例（定稿的 C1–C6 没有这一格），也是 §2.2"$onehot0 每拍成立 ⇒ 无争用"的反证：同拍互斥是**必要非充分**。**
**⇒ 也是 F12（`FIX-2` 与 `FIX-2'` 不等价）的硬证据**：同一条目丢失，`FIX-2` 下 `fin_push` 的 `snd_nxt==snd_una` 仍成立 ⇒ 下一轮扫描（256 拍）自愈重推；`FIX-2'` 的预留正好把这个条件**永久打掉**。

**修法（必须写进纸）**：① `start_ack` 增 `&& !ctrl_slot_busy`；② 定义槽的生命周期 = `[start_ack, 该控制帧 T_DONE]`（或双缓冲两槽）；③ Gate 增"控制帧守恒"判据（发起数 vs 上线数，见 F8）。

## F3 `rx_idle` 的定义不覆盖**重放**与**控制帧校验和**两个忙态

定稿 §1.2 把 `rx_idle` 定义成 UDP 模板那一条：`(rx_state == RX_IDLE) && recv_first`（对标 `rtl/udp_tx_frame.v:87/134/201`，只有 RX_IDLE/RX_FIN/RX_FLUSH 三态）。但：

- **重放**：母件 `P7B_SINGLE_FLOW_10G_DESIGN.md:203`(h) 写明"重放帧也要向 RX 引擎申请 bank（`!bank_rdy[rx_bank]`）"，而重放占 RX 引擎的时长 = 整段 ring 读（~183 拍）。若实现把重放放进**第 4 个 `rx_state`**（或独立引擎）而 `rx_idle` 仍只查 `==RX_IDLE && recv_first` ⇒ 重放期间 `rx_idle` 可能为真 ⇒ **活数据帧与重放帧同时往同一 bank 写**（载荷交错）/ **两个 RX_FIN 同拍**（`upd_wr_data` 双驱动，§2.2 的互斥表整张失效）。
- **校验和**：`checksum16` 是**单实例**（`:636-643`），TCP 版 RX 引擎在收帧期间连续 `den`（`:619-620`），收尾 4 拍（`csum_aen` `wait_cnt<=2` + `csum_fin` `==3`，`:624-632`）。控制帧**无载荷但不是无校验和**（伪头 + 20 B TCP 头）。定稿没写"控制帧的校验和在哪个窗口算"；若在 `start_ack` 后紧接的几拍算，则**必须把 RX 引擎占住**（否则数据流的 `den` 会污染它 → **ACK/FIN 的 TCP 校验和错 → 对端静默丢弃**）。
- 两条都**没有对应的门**：Gate A 无"重放与活帧不重叠"见证、无"逐帧 TCP/IP 校验和 oracle"。

**修法**：`rx_idle` 重新定义为"**RX 侧串行器空闲**"（含 `RX_RING`、含控制帧校验和窗口），并在 §1.2 表里逐条给出；判据补 (i)(ii)（见 F8）。

## F4 `s_axis_tready` 只在"帧首拍"为 1（字面执行 §1.2 会死锁）

定稿 §1.2 的行："`start_data` / `s_axis_tready` | … | `rx_idle && … && !fifo_full && !bank_rdy[rx_bank] && …`（**两处逐字同门**）"，而"其余条件逐字保留"+"把 `state==S_IDLE` 换成 `rx_idle`"对一个**双子句**表达式是不完整的：现役 `s_axis_tready`（`:473-477`）= `((state==S_RECV) || (S_IDLE 子句…)) && !pay_full`，**定稿没有给出 `state==S_RECV` 子句的翻译**。

- 字面执行 ⇒ `tready = rx_idle && …`，而 `rx_idle` 在收帧期间为 0（`recv_first=0`）⇒ **每帧只收 1 个字** ⇒ 帧永不闭合 ⇒ TX 全线死锁。
- UDP 模板 `:201` 之所以"一个式子管两件事"，是因为它的启动门**没有额外条件**；TCP 必须显式写成 `((rx_state==RX_IDLE && !recv_first) || (rx_idle && !ack_pend_r && … && !tx_blk_sid)) && !fifo_full && !bank_rdy[rx_bank]`。
- 定稿自己引了"坑 10 同门"，但**写出来的式子**正是坑 10 的反面 ⇒ 必须订正（这是纸面缺陷；好在 Gate A 的覆盖见证 `cov_frames≥2000` 会让门自己作废而不是假绿）。

## F5 §2.2 互斥表的前提未定稿：**重放的交接拍在哪**

§2.1 把写源 ① 定义为 `rx_state==RX_FIN && fin_cnt==2`，并在 §1.3-④/§2.2 用"重放帧自己的交接拍"论证 C4。但**重放引擎在乒乓下的落点全篇未给**：是并进同一 `rx_state`（那 §2.2 的状态互斥成立），还是另开一个引擎（那 data×ctrl、data×data 的互斥**都不成立**，同拍双写）。母件只说"重放也要申请 bank"。⇒ **实施前必须定稿**（这是 B1"再锚定点逐拍定义"的未兑现部分）。

## F6 §3-C5 / M6 是**幻影**（"门必然抓"做不到）

- C5 的触发要求"0 长帧的同值写**落在**同连接 FIN 预留的 `+1` **之后**"。但在 FIX-4 统一门下：`start_ack` 要求 `rx_idle`，而 0 长帧的接收期间 `recv_first=0` ⇒ **FIN 的预留必然晚于该帧的 `RX_FIN`**；且其后 `tx_blk`（`fin_req` 电平恒高，`:372`/`app_ctrl.v:1099-1100`）挡住新数据帧。⇒ 顺序被结构钉死。
- 而 `base + 0 = base` 是**同值写**（在它之前没有任何写能改变该值：`svc`/`start_ack` 都要求 `rx_idle`，在收帧期间不可达）⇒ **J_seq_mono 看不见**（单调不减恒成立）。
- ⇒ Gate E 的 **M6（撤 `f_plen!=0` 门 + 注入 0 长帧 ⇒ J_seq_mono 必红）打不出红**。要么废掉 M6，要么把它的判据改成"**0 长帧不得写 ring 游标/不得占窗口**"这类**可观测**的量。

## F7 §3/§4 的变异标号自相矛盾，且 C↔M 不是一一对应

- §3-C4 写"**M5 变异**（推进留 `S_DONE`）必红"，而 Gate E 表里 **M5 = 撤 `!ctrl_adv_inflight_for()` 门 ⇒ `J_fin_resv`**（C6 的变异）。同号两物。
- 覆盖映射实为：C1→M4、**C2→（无专属变异）**、C3→M1、C4→M1（被误标 M5）、C5→M6（幻影，F6）、C6→M5。⇒ "5 反例 ↔ 6 变异一一对应"不成立。
- `$onehot0` 的性质本身没问题：三个 `upd_wr_*` 都是寄存器函数的**组合**信号 ⇒ 同拍断言是合法性质（可写）。但见 F2：它**看不见**跨拍独占。

**"先在现役 RTL 上打等价变异证明门有牙"是否自证式？** —— 不是自证（对现役正确件注入 `w_tap_seq`/`seq_r` 的陈旧值，是正当的故障注入）。但它的**证明范围**只有"灵敏度"：① 它在**没有乒乓结构**的 RTL 上做 ⇒ 证不到新结构的对齐；② 它**不担保 §4 的覆盖见证在门上成立**（见证是**激励**性质：`cov_ctrl_data_write_adjacent ≥ 20` 等缺一条 ⇒ 整门作废）；③ 见 F8(iii)：见证集缺的正是 F1 的那一格。

## F8 门集缺三类判据（这是 F1/F2/F3 能逃逸的原因）

| 缺 | 为什么必须有 |
|---|---|
| **(i) 控制帧守恒**（issued vs 上线，含"每个 start_ack 条目在 N 拍内上线"） | F2 的丢帧/混帧在现有判据下**全绿**（`$onehot0` 与 J_seq_* 都看不见） |

## F12 `FIX-2` vs `FIX-2'`：**不等价**（主张 7 的具体反例就是 F2）

| 维度 | `FIX-2'`（预留@帧首） | `FIX-2`（`+1` 留 `S_DONE` + 末字完成门） |
|---|---|---|
| 条目丢失（F2）后能否自愈 | **不能**：`snd_nxt=F+1 ≠ snd_una=F` ⇒ `fin_push`（`:661`）永久为假 ⇒ 丢 FIN 是**永久**的，且留一条 RTO→1 字节重放的尾巴 | **能**：预留没发生，`snd_nxt==snd_una` 仍真 ⇒ 下一轮扫描（256 拍）自动重挂 FIN |
| C6（1 字节重放）免疫机制 | 靠 `!ctrl_adv_inflight_for()` 门 | **结构性**（`+1` 未落地 ⇒ `svc_rewind=0`，根本不回卷） |
| 共享的其它副作用 | 控制帧在飞期间 `snd_nxt` **领先 1**：窗口账（−1 B 保守，无害）、RTO 武装**提前一个帧期**（`:942-943`，无害）、`blocked/epoch` 不受影响 | `S_DONE` 完成路径新增 `rx_idle/svc → 末字消费` 的**跨引擎路径**（UDP 模板里 TX 引擎对 RX 状态**零依赖**，这是没有先例的新锥）；且需 §2.4 的窗口存在性证明 |

⇒ 定稿写"两者对 seq/ring/重放的**全部结论相同**，只差写在哪一拍"**不成立**：至少"条目丢失"这一支行为相反，且 FIX-2 的 `+1` 落在 `S_DONE` 会让 `upd_val = seq_r + 1` 成为**唯一**在"TX 完成后"才改 `snd_nxt` 的写源，与 FIX-1 的"收完即承诺"语义**不再同构**（`snd_nxt` 从此有两套语义）。**选型裁定应改成**：FIX-2' 为主选（理由成立：不动 TX 完成路径、无窗口存在性问题）**但必须配套 F2 的槽独占门**；FIX-2 降级为"备用方案，且必须重证 `fin_push`/`ring_delta`/跨引擎路径三项"。
