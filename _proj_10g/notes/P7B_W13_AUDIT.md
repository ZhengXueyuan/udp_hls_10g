## 0. oracle 的语义（先钉死，后面所有裁定都从这里推）

源码 = `rtl/app_udp_pattern.v` 的 **HEAD** 版（本审计期间工作区该文件正被另一 agent 修改，
故一律按 `git show HEAD:` 读；行号均为 HEAD 行号）：

| 事实 | 证据（HEAD 行号） | 对本审计的含义 |
|---|---|---|
| 失配**只在 `i_en = 1` 时计数** | `:579` `rx_bad = cmp_hit && i_en && (rx_got !== rx_exp)`；P7B_10G 分支 `:601-608` 的 `rx_bad_v[k] = i_en && (...)` | `i_en = 0` ⇒ **一次都没比**，`W13` 恒 0（结构性假阴性） |
| `i_en = 0` 时 LFSR **钉在 SEED**，使能后从下一个字节按 SEED 起算 | `:890-895` `if (!i_en) rx_lfsr <= SEED;`；头注释 `:66-67` | 判据的相位锚点 = **`i_en` 上升沿**，不是帧边界 |
| 图案流**逐字节连续、帧边界不重锚**、`W13` 是**粘滞字节数** | 头注释 `:45` / `:66`；`:905-908` 累加 | **1 字节插入/丢失 ⇒ 永久失步** ⇒ 有错会以 ≈+载荷字节/帧 报警（该校验器"有牙"的机理） |
| `W10/W11`（收帧/收字节）**不受 `i_en` 门控** | `:909-912` 统计条件 = `rx_ld && rx_sof`（无 `i_en`） | ⚠️ **`ΔW10 > 0` 只是"喂到 app 口"的必要条件，不是"比对过"的充分条件**；还必须 `i_en = 1` |
| 各轮的 `i_en = 1` 怎么确定 | 启动门 = `i_en && i_tx_ready`（`:757`，头注释 `:16`） | 每轮只要板子在发图案流（`W8/W9/W20` 在涨）⇒ `i_en = 1` ⇒ **校验器在武装状态**。**本审计每一行都按这条推**，并单列一栏 |

**由上面得到的"非空判据"的完整前置条件（本审计的统一口径）**：
> `W13` 的增量可以当"载荷内容正确"的证据 ⇔ **同窗 `ΔW10 > 0`（真的喂了）** **且** `i_en = 1`（校验器武装）。

⚠️ 与之配套的**第三个坑（同为既有实证）**：`ISSUE_RX_BYTE_CORRUPTION.md` §6.1（`:205-210`）
—— app 的 RX LFSR **永不重同步**且 `W13` 粘滞，**不重烧就连续测量 ⇒ 相位错开 ⇒ 读到恰好
255/256 = 99.609% 的假失配**；同一段还给了反向价值："这个 255/256 恰好证明**校验器逐字节比对是
精确的、无跳字/重字**"。⇒ 该 oracle 会**双向出错**：没流量时假阴性（本审计的主线），
相位错开时假阳性（255/256）。
