## 0. 三行结论

1. ⭐ **J-P1 的 A/B 核心判别成立**：同一个 P-A 构型（**窗口锁 0 + 在飞数据 > 0** + 对端 raw 注入"重复 ACK、`win=0`"），
   **负臂（0x1C）3 跑 = 0 条探询**（板→对端 ≤100 B 帧里只有 SYN-ACK）；**正臂（0x1D）2 跑 = 3 / 10 条**探询帧
   （55 B、`seq == 当时 snd_una`、`len == 1`、flags `0x18`、payload == 图案流该 seq 的字节）。
2. ⭐ **J-P2 有直接证据**：正臂每次探询后 **8.8 / 13.1 / 44.1 µs** 内对端即回一条 **`win=832`（真窗、非 0）** 的 ACK
   （此前 20 ms 的 ACK 全是 `win=0`）⇒ 设计件 §2.1 的"逼出对端一条带真窗的 ACK"路径**被实测到**；
   同跑 sink 收满 **400 MB 逐字节零失配**。
3. ⭐ **J-P4 退避阶梯被直接测到（P-C(c2b)，正臂）**：6 条探询的间隔 = **20 ms(首档) / 5.000 / 10.000 / 20.000 / 40.000 / 60.000 s**
   —— 单调 + 封顶 60 s，与设计件 §3.1 真值表**逐档相同**；（c2a）另跑复现前 4 档（5/10/20 s）。
   ⚠️ 但**负臂的阶梯对照跑（N4）没有进入武装态**（见 §5-②），故"阶梯 ↔ persist"的对照靠负臂 P-A 的武装态（N2/N3，15–18 s）承担。

**首探询时刻 vs 武装时刻（可读的那一半）**：P2（c2b，天然零窗、无注入）的**首探询 = SYN+20 ms**

P1 的首探询 = **SYN+264 ms**，其武装时刻没有直接仪器（扫描拍粒度的窗口状态没接快照）
⇒ **"首探询 − 武装"只有 P2 那一档的读数**。

## 4. P-C（补充档）

### (c1) SYN 就小（正臂 P3）

- 构型：`p7b_tcp_sink`（refresh 件）**默认 `before_connect`** + `--rcvbuf 2920`（**sink 在读**）。
- 见证：`SINK_RCVBUF_ORDER RCVBUF_ORDER=before_connect rcvbuf=2920`。
- 读数：**探询 = 0**（capA = SYN/SYN-ACK）；400 MB / **759.13 Mbps** / `first_mismatch=-1`。
- ⇒ 与设计件一致：**小窗（非零窗）+ 应用在读 ⇒ persist 不介入**（窗口不进 0 就不武装）。

### (c2) 不读 + 灌满（正臂 P2 / P6；负臂 N4）

**新件**（本目录 `_tools/persist_client.py`，md5 `3fef080c…`；**逐件记 md5 后部署到 `/tmp/p7b_persist/`**）：
连上后**一个字节都不读**，`SO_RCVBUF` 分两档落点（`--order before|after`）。非测速件 ⇒ 不产 `PIN_CPU=` 见证（本档速率读数一律来自 sink / 板侧）。

| 子档 | 跑 | 见证（客户端自报逐字） | 探询 | 阶梯（相邻探询间隔） | 板侧 `W69`(infl,eff) | `ΔW55` |
|---|---|---|---|---|---|---|
| **(c2b) after（先大窗后塌）** | **P2** | `CLIENT_SO_RCVBUF_PRE_CONNECT 131072` → `CLIENT_SO_RCVBUF_SET_AFTER_CONNECT req=2920 now=5840`；`noread=1` | **6** | **20 ms\*, 5.000, 10.000, 20.000, 40.000, 60.000 s**（\*首档 = SYN+20 ms = 武装 + `RTO_LIM`） | infl = 49,640 / **eff = 0**（整跑） | **+1** |

| 对照（负臂同构型） | **N4** | 同 (c2b) | **0**（40 s） | — | infl = 58,400 / **eff = 58,400**（见 §5-②） | 0→1 |

**J-P4 判定口径（照设计件"单调 + 封顶 = 判据；绝对档值 = 门槛"）**：
- **单调 + 封顶 60 s：成立**（P2 的 6 档逐档 = 设计件真值表；间隔用**对端墙钟**测量，误差 < 1 ms）。
- **绝对档值**：首档 `20.00 ms`（`RTO_LIM`）、后续 `5.000 / 10.000 / 20.000 / 40.000 / 60.000 s`（`PS_BASE ×1/2/4/8` 与 `PS_MAX`）
  —— 与设计件 §3.1 的 `Reload(p)` 逐档吻合，且 `5.000 s` 反证了 `1 visit = 1.6384 µs`（`3,051,758 × 1.6384 µs = 5.0000 s`）。
- ⚠️ **本档仍是"绝对档值 = 门槛"的读数**：有 1 次独立复现（P6 的 5/10/20 三档）**逐位相同**，
  但 ⛔ **负臂的阶梯对照（N4）没进入武装态** ⇒ 「只有 persist 会出阶梯」这条**本轮没有正面对照**；
  可用的对照 = 负臂 P-A 的武装态（N2/N3：`eff=0` + 在飞 > 0，15.2 s / 18.4 s）内 **0 条 1 字节帧**（已覆盖前两档 20 ms + 5 s）。

## 5. 未观测到 / 做不到 / 与派单不符（逐条）

① ⛔ **N1/N2 的注入器与快照环各有一次"安静失效"（都已修 + 已登记）**：
   - **注入器**：N1 跑里 `stall_probe.py` 只打了 `PROBE_START`，**没抓到 SYN**（现核：注入器与 sink **同拍启动**，
     Python 绑 AF_PACKET 要 ~百 ms ⇒ SYN 已上线）。处置 = 在 `persist_run.sh` 里给注入器 **2 s 布防窗口**（`PROBE_ARMED` 见证行）；
     N2/N3/P1/P5 四跑注入全部正常。⚠️ **N1 的"0 探询"读数仍然成立**（capA 只有 SYN-ACK），但**它那跑没有注入** ⇒ 负臂主跑按 N2/N3 读。

     处置 = 改成 `p7b_snap.sh snap <tag> <KW>`；**N3 起正常**（N3: 127 点 / `SNAP_FAIL` 0 次）。
     ⇒ **N1/N2 的 `W55/W69` 面没有读数**（N3 有）；这两跑的"0 探询"只由 **pcap + 注入器日志**两条腿支撑。
② ⛔ **负臂的阶梯对照（N4）没有进入武装态**：N4 全程 `W69 = 0xe420e420`（infl = eff = **58,400**，窗口非 0）
   ⇒ 武装条件（`wnd == 0`）不成立 ⇒ **N4 的 0 探询被两条原因同时解释**（无 persist ∧ 未武装）⇒
   **它不是 J-P4 的干净对照**（对照改由 N2/N3 的武装态承担，见 §4 末）。
③ ⛔ **负臂内容面 1 条不归因的观测**：N3 的连接首帧（`seq = ISN+1`，发过 2 次）payload 取自图案
   **另一位置**（`pat_off = 61,320 = 42 × 1460`），而同一连接其余 398 段全落同一相位（`−1460` = S-0 轮登记的"连续模式跨连接相位"）。
   ⇒ 只登记，**不写"缺陷"也不写"无害"**；本轮**没有**能分辨它的仪器（正臂 P1/P2 的 400 / 47 段**全是相位 0**、无此形态）。
④ ⚠️ **对端"微窗 832"形态在本轮反复出现**：正臂 P1 的 episode 与负臂 N2/N3 的对端 ACK 里
   `win ∈ {0, 832}` 交替（`PEER_WIN_TOP`：(832, 313) / (0, 163) …）⇒ 板侧 `W69` 的 `eff` 也在 `{0, 832}` 间取样。
   这与设计件 §9-② 的"**微窗（0 < wnd < MSS）不在本刀覆盖范围**"同族；**本轮的探询都落在 `eff = 0` 的取样上**，
   但 ★「探询当拍的 `snd_wnd` 恰为 0」**没有逐拍仪器**（只有 0.1 s 采样的 `W69`）—— 登记为**判据侧的弱环**。
⑤ ⛔ **"注入 → 首探询 ≤ 20 ms + 3×RTT"没测到（构型原因）**：注入落在天然 episode 之后（正臂）或之内（负臂），
   两臂都不是"注入造出窗口 0"。可读的等价格 = **武装 → 首探询 = 20.00 ms**（P2 天然零窗档）。
⑥ ⛔ **J-P7 的"≤1 扫描周期（1.638 µs）"不可测**（见 §3-J-P7 口径）；只有"拆除后 0 条"。
⑦ ⛔ **`W58 o_retx_active` 在 0.1 s 采样面上恒 0** ⇒ 设计件 L3b 三条件里的第①条（"`W58` 只在一个会话时长内为 1"）
   **本轮无有效见证**（低位电平信号 + 慢采样 ⇒ 结构性看不见；**不许读成"没发生过"**）。
⑧ ⚠️ **`board_frames_after_inject` 这个旁证有口径限制**：注入器只统计**注入结束之后 1.5 s** 内、

⑨ ⚠️ **capC（数据帧）被 `-c 400` 截顶**（N2/N3/P1/P3/P4/P5 都是"收到 > 400、只留 400"）⇒
   "板共发了多少帧"只能给**下界**（在飞量的下界据此算，已在 §2 表里标注）。
⑩ ⚠️ **`--maxbytes` 让部分跑提前结束**（P1/P3/P4/P5 主跑都在 4–6 s 就收满 400 MB / 4 GB，
